# P9.4: Intercom screen and ringing UI

| Behavior | Source | Packet |
| --- | --- | --- |
| A tablet's intercom screen lists the other intercom-capable tablets by their HA area name, or by device name when the tablet has no area, so a person picks a room rather than an id | independent design, ADR 0025 decision 6 | P9.4 |
| Tablets in the caller's own area are not listed for a call, because two speakers in one room feed back and the integration refuses that call | independent design, ADR 0025 consequences, ADR 0028 | P9.4 |
| A listed tablet that is already in a call is shown as being in a call, and a tablet without a microphone is still listed so it can be reached | independent design, ADR 0025 decision 7 | P9.4 |
| A tablet with no microphone still opens the intercom screen and says it cannot start a call, instead of offering a button that would fail | independent design, ADR 0025 decision 7 | P9.4 |
| An incoming call covers the dashboard and the screensaver, wakes the panel, shows who is calling and how long is left to answer, and offers Answer and Decline | independent design, ADR 0025 decision 1, ADR 0028 guard 1 | P9.4 |
| A ring that nobody answers stops at the ring limit and the screen returns to what it was showing, so a call in an empty room does not leave a ringing screen behind | independent design, ADR 0025 decision 1 | P9.4 |
| A call that is up keeps a banner on screen for its whole life, the screensaver included, showing who is connected, how long the call has run and how long is left before the hard limit | independent design, ADR 0025 decision 1, ADR 0028 guard 2 | P9.4 |
| A listen-only tablet says on the call screen that it cannot talk back, while it still answers and hears the other side | independent design, ADR 0025 decision 7 | P9.4 |
| A broadcast's receiver sees who is speaking and gets a Reply button that ends the broadcast and places a two-way call back to the sender | independent design, ADR 0025 decision 2 | P9.4 |
| A broadcast's sender sees that it is broadcasting, how long it has run and how long it has left, with a Hang up button | independent design, ADR 0025 decision 2 | P9.4 |
| A call a person started reads as "calling" until the other side answers, and an answered call reads as "in call", so the screen never claims a connection it does not have | independent design, ADR 0025 decision 6, packet P9.3 decision 9 | P9.4 |
| The intercom screen and a fixed-target call can be opened from a dashboard link — the screen, one device, one area or a broadcast — so a dashboard button or a gesture reaches the intercom without the list | independent design, ADR 0025 decision 6, F-GST-07 | P9.4 |
| An intercom link that names no target, or a target that is not one id, is refused with a reason instead of ringing the wrong thing | independent design, F-DSH-09 | P9.4 |
| A tap on the ring or the call banner does not count as idling the kiosk, so interacting with a call does not dismiss the screensaver behind it | independent design, ADR 0025 decision 1 | P9.4 |
| A tablet that cannot reach HA for the device list says so rather than showing an empty list as if nobody were callable | independent design, ADR 0025 decision 6 | P9.4 |
