# P7.1: On-device wake-word detection

| Behavior | Source | Packet |
| --- | --- | --- |
| A per-device setting, "Wake word", switches continuous microphone detection on and off. It is off on every tablet, new or existing, until a household turns it on, and turning it off closes the microphone rather than muting a filter that keeps reading | F-MGT-03, ADR 0030 item 1 | P7.1 |
| The setting is always per device: a profile cannot carry it to other tablets, because a microphone that is open in one room is not a household-wide preference | F-MGT-03, ADR 0030 item 2 | P7.1 |
| HA shows a "Wake word listening" binary sensor, diagnostic, that is on only while the microphone is actually open and features are being computed. It reads off when the setting is off, when `RECORD_AUDIO` is missing (Fire OS can withdraw it at boot) and while the tablet is playing, so a kiosk never looks like it is listening when it is not | F-HA-02, F-KSK-21, ADR 0029 item 7, ADR 0030 item 3 | P7.1 |
| A "Last wake word" timestamp sensor records when the tablet last accepted the wake phrase, for use as an automation trigger or condition. It has no value before the first detection instead of showing a made-up time | F-HA-04, ADR 0030 item 3 | P7.1 |
| HA shows a "Wake word" event entity that fires each time the tablet detects the phrase in the same room, with the phrase and the detector's confidence as attributes, so automations can trigger on the event itself | independent design, ADR 0030 item 4 | P7.1 |
| Each detection also fires the `tabula_wake_word` bus event with the device's HA id, the phrase and the confidence, so an automation can listen on the bus instead of on the entity; other tablets' detections are filtered out by device | independent design, ADR 0030 item 4 | P7.1 |
| The wake-word entities appear only on a tablet that reports the `wake_word` capability, and only that tablet's own detections reach them; every one of them becomes unavailable when the link to HA is lost and refreshes on reconnect | F-HA-02, F-HA-04 | P7.1 |
| One utterance fires at most one detection: after an accepted detection the detector ignores the phrase for a cooldown, so holding the word or saying it twice in a row does not fill HA's recorder or retrigger an automation | independent design, ADR 0030 item 6 | P7.1 |
| Detection pauses while the tablet plays its own audio (a chime, a media stream), because the tablet has no echo canceller Fire OS exposes; a phrase spoken during playback is not heard and the listening sensor reads off until the sound ends | F-KSK-21, ADR 0029 item 3, ADR 0030 item 7 | P7.1 |
