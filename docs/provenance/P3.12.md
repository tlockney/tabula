# P3.12: Screensaver schedule

| Behavior | Source | Packet |
| --- | --- | --- |
| A daily schedule of up to 12 time slots, each with a start time and a screensaver mode: a slot lasts until the next starts and the last wraps past midnight, with no day-of-week variation; the active slot's mode is the mode used next time (the idle start lands in it), the schedule never starts or stops a screensaver on its own, and the app wakes at the earlier of the idle deadline and the next slot's start, so crossings fire without a settings push | F-SSV-18; ADR 0023 | P3.12 |
| A slot change applies live, crossings and edits by one rule: a running screensaver restarts when the mode it should show changed, both events carrying trigger `schedule` and the started one the mode actually shown (unbuilt modes keep the stand-in); the same mode showing keeps the run, and turning the schedule off reverts to the global mode setting | F-SSV-18; ADR 0023 | P3.12 |
| A slot's overrides resolve against the global configuration and can only turn off overlays it has, never invent them: widgets and At a Glance turn-offs drop their entity subscriptions, the power-off delay restarts the countdown's state (effective when F-SSV-19 ships), presence dismissal is carried (the presence source, F-SSV-24, is a no-op until built), and a fixed slot brightness applies while the slot runs — regardless of the separate-level switch, with null inheriting the global path | F-SSV-18; ADR 0023 | P3.12 |
