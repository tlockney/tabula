# P5.3: Schema-driven settings editor

| Behavior | Source | Packet |
| --- | --- | --- |
| An admin opens a tablet's Settings tab and sees its settings as sections in schema order, with nested groups collapsible and each setting's description as help text | independent design (plan 5.6) | P5.3 |
| A setting is edited with a control that matches its type and the schema's bounds: a switch, a number with a slider, a list of choices, text with its length limit, or a colour with a swatch | independent design (plan 5.6) | P5.3 |
| The At a Glance row is edited as ordered entity rows, with suggestions from Home Assistant's live entities | F-AAG-01 | P5.3 |
| The schedule is edited as ordered time slots, each able to inherit the global value or override it, kept in start-time order | F-SSV-18 | P5.3 |
| One save is one revision: all changed settings travel together and the tablet never sees half a change | F-MGT-01, ADR 0011 | P5.3 |
| A rejected setting comes back with the schema's reason on its own field, and the valid settings in the same save still apply | F-MGT-01 | P5.3 |
| When nothing submitted is valid, nothing is saved and the revision does not change | F-MGT-01 | P5.3 |
| The editor says a change is applied on the tablet only once the tablet reports the new revision; before that it says the change is saved and awaiting the tablet | independent design (plan 5.4) | P5.3 |
| A tablet that is offline keeps the saved change, and the editor says it will receive it when it reconnects | F-MGT-01 | P5.3 |
| A setting the tablet's older settings schema cannot receive is still editable, marked as arriving after the tablet updates | F-UPD-08, plan 5.4 | P5.3 |
| A form with unsaved changes marks the sections that changed and asks before the page is left | independent design (plan 5.9) | P5.3 |
