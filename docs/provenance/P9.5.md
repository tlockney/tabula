# P9.5: Intercom auto-answer

| Behavior | Source | Packet |
| --- | --- | --- |
| A tablet can be set to answer calls with no tap: never (the default), only from the tablets the household names, or from every tablet on the hub; the setting lives in Home Assistant and applies from the next call | independent design, ADR 0025 decision 1, ADR 0028 guard 1 | P9.5 |
| A tablet that answers by itself plays a short tone before its microphone opens, so the far end hears that the microphone came on rather than a room that was already listening | independent design, ADR 0028 guard 1, ADR 0027 (tone on the communication stream) | P9.5 |
| A tablet that cannot capture still rings and is never auto-answered, and a broadcast is never auto-answered: both keep the microphone closed | independent design, ADR 0028, "Listen-only"; ADR 0025 decision 2 | P9.5 |
| Home Assistant refuses to set "only listed callers" while no caller is named, in both the entity and the options flow, and the tablet treats a document that reaches it that way as an ordinary ring | independent design, ADR 0028 guard 1 | P9.5 |
| A declined call, an end from Home Assistant or a tap during the tone's run-up cancels the automatic answer, so an auto-answered call never opens a microphone after it has ended | independent design, ADR 0028 guards 1, 3 | P9.5 |
