# P9.2: Intercom in the integration

| Behavior | Source | Packet |
| --- | --- | --- |
| A `tabula.intercom_call` action rings one tablet for a two-way call, naming the tablet the person speaks from; a target that cannot take part is left out instead of being rung, and a call that would ring nobody is refused with an error rather than reported as started | independent design, ADR 0025 decision 5 | P9.2 |
| The same action with mode `broadcast` starts a live one-way broadcast on the targeted tablets, or on every tablet that can hear when no target is given; the caller is never one of its own targets | independent design, ADR 0025 decisions 2, 5 | P9.2 |
| A two-way call between two tablets in the same area is refused, with an error that says why, because two speakers and two microphones in one room feed back; a broadcast to a tablet in the caller's area is skipped instead, and the broadcast still runs | independent design, ADR 0025 consequences, ADR 0028 | P9.2 |
| `tabula.intercom_end` ends a call by its id or by naming a tablet in it, and reaches every tablet in the call in every state — ringing, connecting, in progress or broadcasting — so a call can always be stopped from HA without a person at the tablet | independent design, ADR 0025 decision 5, ADR 0028 guard 3 | P9.2 |
| An unanswered call is ended by the integration at the ring limit and reported as a missed call, so a call into an empty room is over within a minute and an automation can notify someone about it | independent design, ADR 0025 decision 1, ADR 0028 guard 2 | P9.2 |
| An answered call whose two ends never start exchanging connection details is ended by the connect timeout, and every call ends by itself at the hard call limit, so a call nobody is using cannot run unattended | independent design, ADR 0028 guard 2 | P9.2 |
| A tablet that drops off, or that restarts and registers again during a call, ends the call for the other side; the call is never re-rung or resumed, and a restarted tablet is told to hang up instead of being left showing a call that no longer exists | independent design, ADR 0028 guard 4 | P9.2 |
| Automations can follow a call through four bus events — started, answered, missed and ended — each carrying the call id, caller, callees, mode and, where it applies, the reason it ended | independent design, ADR 0025 decision 5 | P9.2 |
| Every tablet that can hear a call gets an "Intercom" sensor reading idle, ringing, in a call or broadcasting, created only for a tablet that reports the capability and removed if the tablet stops reporting it | independent design, ADR 0025 decision 5 | P9.2 |
| A call started from a tablet's own screen goes through the same directory, gating and relay as one started from an action, so both paths behave alike and a tablet without a microphone cannot start one | independent design, ADR 0025 decision 6, PROTOCOL.md 4.5 | P9.2 |
| The two ends of a call exchange their own connection details through HA, which copies each offer, answer and candidate to the other end without reading or rewriting it, so the audio continues to go directly between the tablets | independent design, ADR 0025 decisions 3, 4 | P9.2 |
