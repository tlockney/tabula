## Why

Intercom is the first-priority feature (ADR 0025). Everything after this packet (integration relay, Android engine, screen) needs the wire format first. This packet adds the `intercom` capability to TLP and teaches the mock device to take part in a call without any audio, so the integration side is testable in CI.

2. Define the frames. ### Frames

Added to TLP v1 as additive, capability-gated changes (PROTOCOL 8), no major bump:

- capabilities `intercom.listen` and `intercom.talk` (ADR 0025 decision 7);
- commands `intercom_ring` (`call_id`, `caller_device_id`, `caller_name`, `mode`), `intercom_signal` (`call_id`, `kind`, `payload`) and `intercom_end` (`call_id`, `reason`), all gated by `intercom.listen`;
- events `intercom_answer`, `intercom_decline`, `intercom_signal`, `intercom_ended` and `intercom_start_request` (the last gated by `intercom.talk`, since starting a call needs a microphone), all relayed to one `tabula_intercom` bus event;
- state key `intercom_state` (`idle`, `ringing`, `in_call`, `broadcasting`), where a device playing a broadcast is `in_call` and only the sender is `broadcasting`.

`call_id` has the same form as `command_id` and is chosen by whoever starts the call: the integration for an HA-started call, the device for one started on its own screen. The new `$defs` are `intercom_call_id`, `intercom_mode`, `intercom_signal_kind` and `intercom_end_reason`; `payload` is bounded at `INTERCOM_SIGNAL_MAX_BYTES`.

### Constants (ADR 0002, "Intercom")

| Name | Value | How it was chosen |
| --- | --- | --- |
| `INTERCOM_RING_LIMIT_S` | 45 s | already in ADR 0002 from ADR 0028; recorded in the mock and `:core` |
| `INTERCOM_CONNECT_TIMEOUT_S` | 10 s | same |
| `INTERCOM_CALL_LIMIT_S` | 300 s | ADR 0028 guard 2 requires a hard limit but leaves the value to this packet. 300 s is longer than any across-the-house conversation and short enough that feedback cannot run unattended for an hour. **Provisional: the owner confirms or changes it.** |
| `INTERCOM_SIGNAL_MAX_BYTES` | 4096 B | Measured, not guessed: a synthetic Opus offer of the shape the P9.0 spike logged (`sdpLines=38`, `m=audio ... 111 63 9 0 8 13 110 126`, four extmaps, a sha-256 fingerprint, two SSRC lines) is 1 322 bytes of SDP, or 1 396 once JSON-escaped into the frame; an ICE candidate is about 120 B. 4 KiB is roughly three times the measured offer, admits another codec or extmap, and keeps one relayed frame far under `FRAME_MAX_BYTES`. The measured offer is the `command_intercom_signal.offer.json` fixture, so the bound and the fixture cannot drift apart. |

What the tests cover:

- **Fixtures.** 12 new valid fixtures (three commands, the broadcast variant, two signal kinds, five events, the area target, `state_delta.intercom`) and nine invalid ones, each pinned to the path it must fail at in `invalid/EXPECTED.json`.
- **Kotlin codec.** Every fixture decodes strictly and re-encodes unchanged (`TlpFixturesTest`), the three command frames round-trip through their typed args, each event's data round-trips typed, and `IntercomFixturesTest` reads the call id, caller, mode, signal payload and target out of the fixtures. `TlpCodecTest` covers the start request's one-target rule, the payload byte bound, the dotted capability name and an `intercom_ring` decode.
- **Mock device state machine.** Ring → answer → hard limit; ring → ring limit ("timeout"); decline; a second ring answering `busy`; `intercom_end` with the wrong call id changing nothing; broadcast entering `in_call` with nothing to answer; signals recorded and refused for another call or over the size bound; a reconnect ending the call with `disconnect` and nothing on the next one; `intercom_start_request` target rules; and the three commands NACKing `unsupported_command` on a device that does not declare `intercom.listen`.
- **Conformance.** `test_intercom_is_negotiated_and_commands_are_gated` checks both halves visible from this side: the capability is absent from `register_result`, and the device refuses the commands anyway. The integration's side of "never sends it" is P9.2's.
- **Session.** Ring, answer and hang up over the real socket, the signal relay in both directions, and a declared device being accepted with `intercom_state: idle`.

### Deviations

1. **The frames were not generated.** The packet's step 3 says to "regenerate the Kotlin codec with `tools/codegen.py`". That tool generates the settings classes only (`Settings.kt`); the TLP codec in `android/core/.../tlp/` is hand-written and has no generator, and P2.0's merged work left it that way. The new types were added by hand and `TlpFixturesTest` is what keeps them honest against the schema. No `codegen` change was invented for it.
2. **The capability name pattern had to admit dots.** `register.capabilities` items required `[a-z][a-z0-9_]{0,31}`, which rejects `intercom.listen`; a device declaring the ADR's capability could not have registered at all. The pattern is now one to three dot-separated segments of that same form (ADR 0002's bound row updated with it), PROTOCOL 4.0 and 8 say so, and an invalid fixture pins a name of the wrong shape. This is a loosening for senders only: an integration older than this change still ignores an unknown name it can parse.
3. **The integration relays the events now.** Its `BUS_EVENT_TYPES` table must cover every v1 event, so without the five entries the wire-level conformance run fails with `unknown_error` on `event.intercom_decline` and friends. They map to `tabula_intercom` (the family naming of `tabula_notification` and `tabula_media`), which is what PROTOCOL 4.7 now documents. Services, entities, the call relay, ringing and the screen stay in P9.2 and later, as the packet says.
4. **No timer constant was invented for the mock's deadlines.** The ring limit and the hard limit are checked by `check_intercom_timers()` against the mock's existing injectable clock (the P3.15 pattern), which the unit tests drive; every command checks them too, so a live mock notices on its next one. A background loop would have needed a tick interval that no ADR names.
5. `test_every_command_fixture_is_answered` now allows `busy` among the NACKs it accepts, because the fixture set rings the same mock twice.
6. The two constants ADR 0028 had already chosen were left exactly as they were; this packet only added rows for the two it owns.

Nothing here changes the audio rule: the mock has no microphone and no player, and the payload is the peer's own signaling text, which HA relays without reading it.
