# P1.1 — Mock device

Side: build   Tier: standard   Depends on: P0.4
Verification: ci
Issue: #9
Status: in-review

## Why

A Python reference device lets the integration be built and tested in CI without a tablet, and its conformance suite checks any TLP server.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 5 and 7.2 (P1.1), section 8
- `docs/PROTOCOL.md`
- `docs/decisions/0002-constants.md`
- `schema/fixtures/`

## Do

1. Create `mockdevice/`: a Python CLI that speaks TLP. Pairing and claim, register, state pushes, command handling with `tabula/result` ACKs (configurable failure and delay modes), reconnect.
2. Validate the mock's own frames against the fixtures.
3. Add `mockdevice/conformance/`, which replays fixture sequences against any TLP server and checks responses.
4. Add Makefile targets so `make test` runs the mock's tests.

## Out of scope

- The HA integration (P1.2). End-to-end pairing against HA is checked there.

## Done when

- `make test` passes the mock unit tests.
- Every fixture in `schema/fixtures/` round-trips through the mock's codec (test output pasted).
- `make check` passes.

## Hand back

Result section: CLI usage, test output.

## Result

Changed:

- `mockdevice/` (uv workspace member `tabula-mockdevice`):
  - `codec.py`: strict encode (sender), tolerant decode (receiver, `additionalProperties` relaxed), `FRAME_MAX_BYTES`, server message classification.
  - `pairing.py`: pair request, claim polling, `/auth/token` refresh without `client_id`; `invalid_grant`/403 is final.
  - `client.py`: register, subscribe, coalesced state pushes, command loop with exactly one result per command, events, log streaming, `ping` keepalive, superseded handling, equal-jitter backoff.
  - `device.py`: simulated state and command handlers with `--fail`, `--drop`, `--delay` modes; redaction, origin check for `navigate`, per-connection settings revision rule.
  - `testserver.py`: in-process TLP server (the integration's side of PROTOCOL.md without HA) that validates every received frame strictly. Reusable by P1.2's tests.
  - `cli.py`: `tabula-mockdevice pair` and `run`.
  - `tests/`: codec fixture round trip, device logic, sessions against the test server, CLI.
  - `conformance/`: replays fixtures against `TABULA_HA_URL` (with a paired `TABULA_STORE`), else the test server.
- Root `pyproject.toml`: workspace, `pytest-asyncio`, test paths. `Makefile`: `mock-test`, `conformance`.
- `docs/packets/P0.4-tlp-v1.md`: deviation for FEATURES.md details v1 leaves out (review follow-up from PR #31).

PROVENANCE: no user-visible behavior (development tool).

CLI usage:

```text
usage: tabula-mockdevice [-h] --ha HA [--store STORE] [-v] {pair,run} ...

Python reference device for TLP v1.

positional arguments:
  {pair,run}
    pair         pair with Home Assistant and store the credential
    run          connect and serve commands until interrupted

options:
  -h, --help     show this help message and exit
  --ha HA        Home Assistant base URL, e.g. http://ha:8123
  --store STORE  device file (default /root/.config/tabula-
                 mockdevice/device.json)
  -v, --verbose
usage: tabula-mockdevice run [-h] [--capabilities CAPABILITIES] [--fail FAIL]
                             [--drop DROP] [--delay DELAY]

options:
  -h, --help            show this help message and exit
  --capabilities CAPABILITIES
                        comma-separated capabilities to declare
  --fail FAIL           comma-separated commands that NACK with 'failed'
  --drop DROP           comma-separated commands that never answer
  --delay DELAY         seconds before answering a command
```
