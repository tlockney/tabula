# P9.6 — Voice-started intercom calls (Assist intents)

Side: build   Tier: standard   Depends on: P9.2, P7.3
Verification: ci
Issue: #146
Status: in-review

## Why

Thomas requires that a call can be started by voice from the first intercom release (ADR 0025 decision 8). This is also how the tablets take over from the household's existing voice speakers. With the satellite entity (P7.3) and the call service (P9.2) in place, this packet adds the Assist intents.

- `AGENTS.md`
- `docs/decisions/0025-intercom.md` (decision 8), `0024-voice-satellite.md`
- `docs/packets/P9.2-intercom-integration.md`, `docs/packets/P7.3-assist-satellite-entity.md`

- HA core `intent` and `conversation` helpers (`homeassistant.helpers.intent`, custom sentences for the `conversation` integration; Apache-2.0)

## Do

1. Intents "call the <area or device>", "call <person>" and "broadcast <message>"; the caller is the satellite device that heard the request. A person maps to a device or area in the integration's settings (options flow; stored per config entry; default empty).
2. Register the intents and sentences only when at least one device declares both `voice` and `intercom_talk`. Sentences in English; the structure allows other languages later.
3. The intents call the same code path as `tabula.intercom_call` (P9.2), so every guard applies. An unknown person or area answers with a spoken refusal, not silence.
4. Tests with HA's conversation test helpers and the mock device: each intent, unknown target, caller device lookup, same-area refusal, intents absent without a capable device.
5. `docs/provenance/P9.6.md`: independent design.

## Out of scope

Android changes, the satellite entity itself, speech tuning.

## Hand back

Result: pasted output, sentences registered, deviations. Add `needs-review` with the head SHA; ask for a second independent reviewer (voice).

The four production guards from ADR 0028 are requirements, not options: (1) a call starts or is answered only through an explicit action or a schedule, never because a device is online; (2) a hard call time limit; (3) `tabula.intercom_end` reaches every device in the call in every call state; (4) no call resumes after a device restarts.

Audio rule (owner, binding): no test, script or run in this packet plays or captures audio on a household device unless the owner schedules it. Silent analysis, unit tests and CI are fine. Do not run `tools/device/check_p90*.sh`, `check_p70.sh` or set `TABULA_AUDIO_OK`.

### Deviations

1. **"broadcast \<message\>" is delivered as "broadcast", not as an intercom intent.** HA's `HassBroadcast` already announces a spoken message through every satellite on the P7.3 announce path, and an intercom broadcast is live one-way audio with no text on the wire (ADR 0025 decision 2). Two intents for the same words would shadow each other, so this packet registers the live forms and leaves the announcement to HA; a household that says "broadcast dinner is ready" gets exactly what it got before P9.6. ADR 0036 decision 8.
2. **The options flow is a menu.** Per-tablet settings and the intercom names are two steps behind `async_step_init`, because the names needed a home that is not a device. The tablet editor itself is unchanged; its tests now open the menu first.

### P9.2's open questions

1. **An HA-started call cannot reach its own caller's engine** — unchanged, and it is the one thing a voice-started call cannot do for itself. The callee is rung with the caller's ids and every guard answers out loud, so the request, the resolution and the refusals are complete and tested; the caller's own capture still needs the protocol frame P9.2 asked for, and this path inherits it without a change here. A voice-started call is therefore complete up to the ring, which is stated plainly in ADR 0036's Consequences rather than papered over.
2. **A stale `intercom_state`** — untouched by this packet: no new frames, and the boot/limit guard remains P9.3's.
3. **`INTERCOM_CALL_LIMIT_S`** — still the owner's to confirm; voice-started calls use it unchanged.

### Audio rule

No device, emulator or `tools/device` script was run, `TABULA_AUDIO_OK` was never set, and no audio was played or captured. Every test drives the mock device and HA's conversation helpers only. No `PeerConnection` was opened.
