## Why

The core of the integration: a hub entry, secure pairing and per-device credentials, and the WebSocket API devices register on. Security-sensitive.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 5.1–5.4, 7.2 (P1.2) and 9
- `docs/PROTOCOL.md`
- `docs/decisions/0001-ha-platform.md`, `docs/decisions/0002-constants.md`
- `mockdevice/` README

## Do

1. Create `integration/custom_components/tabula/`: hub config flow, pairing and claim views, discovery flow, per-device user creation per ADR 0001.
2. WebSocket command registration with connection binding, version checks, device registry entries, newest-connection-wins, diagnostics.
3. Add Makefile targets so `make test` runs the integration tests (pytest-homeassistant-custom-component) and the mock conformance suite.

## Out of scope

- Entity platforms (P1.3), commands (P1.4), settings (P1.5).

## Done when

- `make test` passes, with tests for: pairing happy path end to end with the mock; wrong code rejected; claim with the wrong nonce rejected; credential released once only; rate limit and pending cap hold; pending entries expire; unpaired device_id rejected with no side effects; a device's credential cannot act for another device; unsupported protocol major rejected with a repair issue; double registration leaves one device on the latest connection; deleting the device revokes its credential; diagnostics contain no credential.
- `make check` passes.

## Hand back

Result section: test output, any deviation from ADR 0001.

## Result

Built `integration/custom_components/tabula/`: manifest, hub config flow (one entry by
unique_id, discovery flow started by a pair request), unauthenticated pair/claim HTTP
views, per-device system user + refresh token creation, `tabula/*` WebSocket commands
(register, subscribe, state, result, event, log) with connection binding, protocol
version check with a per-device repair issue, newest-connection-wins supersession,
device-registry adoption, and diagnostics (config entry + device). The TLP JSON schema
is bundled with the component and `tools/validate_frames.py` now enforces the bundled
copy matches `schema/tlp-v1.schema.json` byte for byte at `make check` time.

Tests under `integration/tests/` drive the real HTTP and WebSocket surfaces (no mocks of
the integration): 47 tests — pairing happy path and every refusal path, credential
released once, rate limits, pending cap and expiry, unknown-device no-side-effects,
cross-device binding, supersession (subscribed and register-only), revocation on device
delete / entry removal / orphan sweep, diagnostics without credentials, and end to end
with the mock device: `tabula-mockdevice pair` as a real subprocess, the TLPClient
library registering and streaming state, and the mock conformance suite replayed
against the integration over the wire (`TABULA_HA_URL`/`TABULA_STORE`).

The conformance suite run against the integration caught one real bug, now fixed with
a regression test (`test_register_only_connection_is_superseded`): a register-only
connection displaced by a newer registration answered `not_registered` instead of
`superseded`.

Deviations / decisions:

- HA 2026.2.3 ships no rate limiter for plain HTTP views (the old
  `KeyRateLimitMiddleware` is gone), so the pair/claim views carry an in-repo per-IP
  sliding-window limiter with the ADR 0002 constants (`PAIR_RATE_LIMIT`,
  `CLAIM_RATE_LIMIT`, `PAIR_RATE_WINDOW`); over the limit answers the `rate_limited`
  http_error with `Retry-After`.
- aiohttp freezes the HTTP router once HA's server is running and HA 2026.2 has no
  `unregister_view`, so the pair/claim views are registered once at component setup
  (`async_setup`), are stateless, resolve the live hub per request, and answer a plain
  404 when the hub entry is not loaded (the TLP http_error enum has no code for
  "integration not set up"). This mirrors HA's own order: views exist before the server.
- WebSocket commands use `vol.All(vol.Schema({vol.Required("type"): command},
  extra=vol.ALLOW_EXTRA))` so whole TLP frames reach the handlers (the type-only dict
  form caps a message at 2 keys); handlers then validate against the bundled JSON
  schema. This is the documented escape in `websocket_api/decorators.py`.
- Superseded sessions stay in the session table so they keep answering `superseded`
  (PROTOCOL.md 4.9); the cleanup runs when the socket closes, registered under the
  frame's msg id, so register-only sockets cannot leak. Deviation from ADR 0001's
  sketch only in mechanism, not in behavior.
- Device users: `GROUP_ID_USER` via `homeassistant.auth.const` (not a local constant),
  names "Tabula <id8>", `local_only=True` by default, hub option `local_only` to
  disable; tokens are revoked before the user (ADR 0001 item 3), which also closes the
  device's live socket (HA registers a per-connection revoke callback).
- The integration package requires Python >= 3.13.2 (homeassistant 2026.2.3 pin,
  ADR 0001 item 8) and joins the uv workspace; root pytest config gains
  `integration/tests` and `pythonpath` entries.
- pytest-homeassistant-custom-component's plugin disables sockets for every test in
  the venv once it is installed (which the workspace merge makes repo-wide), so
  `mockdevice/tests/conftest.py` and `mockdevice/conformance/conftest.py` declare an
  autouse `socket_enabled` fixture — those suites exist to exercise real sockets.
- The end-to-end CLI test runs `tabula-mockdevice pair` with `PYTHONUNBUFFERED=1` so
  the pairing code line reaches the pipe promptly, and kills the subprocess on
  failure so HA's thread check stays clean.
- Options flow deliberately omitted (P1.5 scope).

No ADR 0001 constants were invented; all come from `docs/decisions/0002-constants.md`.
Prior art: standard HA custom-integration patterns (config flow, views, websocket
command registration, device/issue registries) as used in HA core and the HA Companion
app; no third-party code was copied.
