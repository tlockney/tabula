# P0.4 — TLP v1 and constants

Side: build   Tier: deep   Depends on: P0.3
Verification: ci
Issue: #7
Status: in-review

## Why

The Tabula Link Protocol is the contract between the integration, the mock device and the Android app. Its golden fixtures are what all three test against.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` section 5 and 7.1 (P0.4), section 8
- `docs/decisions/0001-ha-platform.md`
- `docs/FEATURES.md` (if P0.2r is done; not a dependency)

## Do

1. Write `docs/PROTOCOL.md`: pairing and claim, register/registered (protocol and schema versions, capabilities, settings revision), state deltas, command frames with `command_id`, result frames, `set_settings`, events, log subscription, the HTTP screenshot upload, reconnect/backoff rules and the version compatibility rules (plan 5.4). Each frame type gets a JSON Schema definition.
2. Write `docs/decisions/0002-constants.md`: protocol timeouts, backoff bounds, rate limits and the Phase 1–2 behavior defaults.
3. Add a golden fixture for every frame type in `schema/fixtures/`.
4. Write `tools/validate_frames.py` and wire it into `make check`.

## Out of scope

- Integration, mock device or Android code.
- Settings schema (P0.5).

## Done when

- `make check` runs `tools/validate_frames.py` and it validates every fixture in `schema/fixtures/` against the schemas in `docs/PROTOCOL.md`.
- Every frame type in `docs/PROTOCOL.md` has at least one fixture.

## Hand back

Result section: frame type list, fixture count, validator output.

## Result

Changed:

- `docs/PROTOCOL.md`: TLP v1 (pairing and claim, credential use, WebSocket session, register, subscribe, state deltas, commands with `command_id`, results, events, logs, screenshot upload, errors, reconnect and backoff, versioning, fixture layout).
- `docs/decisions/0002-constants.md`: every constant PROTOCOL.md names, schema bounds, and Phase 1–2 behavior defaults, each with its reasoning.
- `schema/tlp-v1.schema.json`: one `$defs` entry per frame type, listed in `x-tabula-frames`.
- `schema/fixtures/tlp/v1/`: 37 valid fixtures, 15 must-fail fixtures in `invalid/`.
- `tools/validate_frames.py` + `tools/tests/test_validate_frames.py`; `make frames` added to `make check`; `jsonschema` added to the dev dependencies.

Deviation: the brief says the schemas live in `docs/PROTOCOL.md`. They live in `schema/tlp-v1.schema.json` instead, which PROTOCOL.md references by `$defs` name, so code (mock device, integration, Kotlin codegen) loads one file rather than parsing Markdown. Same pattern as the settings schema (plan 5.6).

Deviation from plan 5.1: the screenshot upload is `POST /api/tabula/screenshot` with no device ID in the path; the device is resolved from the token (connection binding).

Frame types (28): register, subscribe, state_delta, command_result, event, log, register_result, ack, error_result, command_set_settings, command_screen, command_notify, command_play_media, command_media_control, command_screensaver, command_navigate, command_reload, command_restart_app, command_clear_cache, command_log_subscription, command_screenshot, http_pair_request, http_pair_response, http_claim_request, http_claim_pending, http_claim_response, http_error, http_screenshot_response.
