# P3.12 — Screensaver schedule

Side: build   Tier: standard   Depends on: P3.1
Verification: hardware
Issue: TBD
Status: ready

## Why

F-SSV-18: an optional list of daily time slots, each with a start time and a mode; a slot lasts until the next starts and the last wraps past midnight. Slots may override brightness, the panel power-off delay, presence dismissal, widgets and At a Glance — but only turn off overlays configured globally, never invent them. Edits apply live, including to a running screensaver. The `schedule` trigger value for `tabula_screensaver` events already exists in TLP v1.

The engine is independent of the other mode packets and can run in parallel with them, but its hardware check can only exercise mode switching among the modes that exist when it runs; the script tests with clock and black first and the verifier adds other modes if their packets have landed.

## Do

1. The schedule engine (plain JVM): slot lookup for a wall-clock time, wrap-past-midnight, live re-resolution when settings change mid-run (including the running screensaver), and crossing into a slot. No day-of-week variation.
2. Entering a slot: switches the mode used next time; if the screensaver is running, it restarts in the slot's mode with trigger `schedule`; the event carries the mode actually shown (ADR 0013 item 3's stand-in rule still applies for unbuilt modes).
3. Slot overrides: brightness (fixed level or inherit global/adaptive — via the existing override path), widgets and At a Glance (turn-offs only, checked against global configuration), presence dismissal (P3.12 applies the flag; the presence source itself is out of scope and a configured-but-unbuilt feature is a no-op). The `power_off_delay` override is carried but no-ops until F-SSV-19 ships (noted in P3.1).
4. Crossing into a slot with a different power-off delay restarts that countdown — implemented as state now, effective when F-SSV-19 lands.
5. JVM tests: slot lookup across midnight, live edits, restart-on-cross, override resolution (cannot invent overlays), event trigger.
6. `tools/device/check_p312.sh` and a DEVICE.md section (slots set a few minutes ahead so the check runs quickly; `ha_events.py` captures the `schedule`-triggered events).
7. `PROVENANCE.md` rows.

## Out of scope

- F-SSV-19 (panel off after a while) and F-SSV-20 (wake behavior) as features.
- The HA presence source (F-SSV-24).
- Now-playing override (Phase 8).

## Done when

- CI: `make check` passes with the new JVM tests.
- Hardware (pasted by the hardware verifier): with a slot for the next few minutes set to `black` followed by one for `clock`, an idle tablet enters the black screensaver at the slot time, then restarts in clock mode at the second slot; HA shows both `tabula_screensaver` events with trigger `schedule`; editing the running slot's brightness applies live. `check_p312.sh` output pasted.
- `PROVENANCE.md` updated.
