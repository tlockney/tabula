# P3.16 — Ambient light sensor entity (illuminance)

Side: build   Tier: standard   Depends on: none
Verification: hardware
Issue: #86
Status: ready

## Why

The tablet's light sensor already drives adaptive brightness on the device (P2.3, ADR 0011), but HA cannot see the reading. F-HA-06 describes an illuminance sensor entity and leaves open whether to expose it; Thomas decided to expose it (2026-11-21). With it, HA automations can use the room's light level, and the readings are visible when tuning the brightness curve and the night-mode threshold.

## Do

1. Protocol: a new state key `illuminance` (lux, number ≥ 0) gated by a new `illuminance` capability, additive per PROTOCOL 8. Update PROTOCOL 4.4 and the TLP schema, with valid and invalid fixtures.
2. Rate limiting (F-HA-06): a real change is sent at once; small oscillation is not. Pick a relative change threshold and a minimum interval for sub-threshold changes, and record both in an ADR 0002 extension with reasons. The existing `STATE_MIN_INTERVAL` coalescing still applies on top. Put the filter in plain JVM code in `android/core` so it is unit-tested.
3. Device: declare `illuminance` only when the tablet has a light sensor (F-HA-02). Report from the same `LightSensor` listener that feeds adaptive brightness; do not register a second listener. Include the current value in `register`. If the sensor stops reporting while the panel is off (F-SCR-14, also checked in P3.4's spike), keep the last value; do not send `null` or zero.
4. Integration: a `sensor` entity with device class `illuminance`, unit `lx`, state class `measurement`, created only with the capability. It becomes unavailable with the rest of the device on disconnect (F-HA-04). Not a diagnostic entity: it is meant for automations.
5. Record in a short ADR (or a section of ADR 0009) that F-HA-06 ships, and why the entity is not diagnostic.
6. Mock device: declare the capability and emit readings, so the conformance suite and integration tests cover the round trip.
7. Tests: JVM tests for the filter (step change goes out at once, oscillation is throttled, last value held); integration tests for entity creation with and without the capability and for state updates.
8. `tools/device/check_p316.sh` and a DEVICE.md section; `PROVENANCE.md` row.

## Out of scope

- An HA illuminance entity as the source for adaptive brightness (F-SCR-05; deferred by ADR 0011).
- The user-shaped brightness curve (F-SCR-06).
- Night mode (P3.4).
