Side: build   Tier: standard   Depends on: P0.4, P0.5
Verification: ci
Issue: #14
Status: done

## Why

The Android app needs the TLP codec and typed settings, tested against the same fixtures as the integration.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 6, 7.3 (P2.0) and 8
- `docs/DEVELOPMENT.md`
- `docs/PROTOCOL.md`
- `schema/settings.schema.json`, `schema/fixtures/`
- `docs/decisions/0001-ha-platform.md` (minSdk)

## Do

1. Create the Gradle project in `android/` (package `net.lockney.tabula`), minSdk per ADR 0001, targetSdk per a new ADR.
2. Implement the TLP frame codec.
3. Write `tools/codegen` to generate Kotlin settings classes from the schema.
4. JVM unit tests run the codec against `schema/fixtures/`.
5. Add Makefile targets so `make check` runs the Android unit tests and a codegen-drift check. Toolchain from package registries only (AGENTS.md rule 7).

## Out of scope

- Android services, UI or networking (P2.1+).

## Done when

- `make check` passes in CI, including `./gradlew test` and a codegen run that produces no diff.

## Hand back

Result section: test output, targetSdk ADR number.

## Result

### What was built

- `android/` Gradle project: `:core` (plain Kotlin JVM — the codec, no Android framework dependencies) and `:app` (com.android.application, namespace `net.lockney.tabula`, minSdk 24 per ADR 0001, targetSdk/compileSdk 34 per **ADR 0007**).
- TLP v1 codec in `net.lockney.tabula.core.tlp`: typed data classes for all 30 frame types plus the shared `state`/`log_line`/`error` types, validating every schema bound, pattern, format and conditional in `init` blocks (so a value that exists is a valid one). `Tlp` offers a strict decoder (matches `tools/validate_frames.py` verdicts; used by the fixture tests) and a tolerant one (ignores unknown members, PROTOCOL 4.0) for received frames, plus `encodeFrame` enforcing `FRAME_MAX_BYTES`.
- `tools/codegen.py` generates `android/core/src/main/kotlin/net/lockney/tabula/core/settings/Settings.kt` from `schema/settings.schema.json` (committed), raising on any schema construct it does not support; `--check` gates drift. `SettingsCodec` (hand-written) decodes/encodes documents strictly, omitting default-valued members on encode.
- Make targets: `setup-android`, `android-test`, `codegen`, `codegen-drift`, `android`; `make check` = `lint frames test android site`.
- CI (`.github/workflows/ci.yml`): `actions/setup-java` (temurin 17) + `android-actions/setup-android`, then `make setup-android` and `make check` with `TABULA_REQUIRE_ANDROID=1`, which turns any skip in the Android step into a failure.
- ADR 0007 records targetSdk 34, the pinned toolchain (Gradle 8.14.8 distribution and wrapper-jar SHA-256s, AGP 8.13.2, Kotlin 2.4.21, kotlinx-serialization 1.13.0, JDK 17–21, platform android-34 / build-tools 34.0.0) and the CI sources; `docs/DEVELOPMENT.md` documents `make setup-android` and its network needs (dl.google.com, services.gradle.org, Google Maven, Maven Central — all pinned or checksum-verified).
- Python tests for the generator in `tools/tests/test_codegen.py`.

### Deviations / decisions

- **targetSdk ADR: 0007** (`docs/decisions/0007-android-toolchain-and-targetsdk.md`), including the Gradle wrapper distribution (8.14.8, both published checksums recorded) and the CI toolchain actions.
- **Strict state decode.** PROTOCOL 4.8's "ignore an unknown state value for that frame" rule applies to receivers of `tabula/state` — in v1 the device only ever sends state, never receives it, so the Kotlin codec decodes state strictly and the tolerance rule stays with the integration (Python). Received frames (commands, results, acks, register_result, pong) do use tolerant member-ignoring per PROTOCOL 4.0, and an unknown enum value in command args surfaces as a decode failure the command layer reports as `invalid_args` (PROTOCOL 4.8).
- **Settings decoded strictly** (unknown keys rejected): the schema sets `additionalProperties: false`, and a device only receives documents at or below its own `schema_version` (HA translates down, plan 5.4), so an unknown key means the peer is not speaking this schema.
- **Absent groups materialize as default instances.** The Python side treats missing group objects as absent; Kotlin materializes `Identity()`, `Connection()` etc. — the same reading as "a key HA does not send keeps the device default" (PROTOCOL 4.5). `empty.json` and `defaults.json` decode equal.
- **`command_result.data`, command `args` and `set_settings.settings` are kept as raw JsonObject** with typed accessor functions, so nothing the typed layer does not yet model is lost; strict decode validates them through the typed classes.
- **Round-trip comparison details** (test-only): explicit JSON null vs absent member are treated as equal, and numbers compare numerically (a `position` of `42.5` round-trips through a `Double`).
- **`java.time` in `:core`.** Fine for JVM tests; ADR 0007 notes P2.1 must enable `coreLibraryDesugaring` in `:app` for minSdk 24.
- **AGP 8.13.2 / Gradle 8.14.8 rather than the 9.x majors** — one deliberate generation behind for a codec-only module; reasoning and upgrade path in ADR 0007.
- **No PROVENANCE.md entries**: the codec and codegen are internal; every user-visible behavior they encode (settings defaults, protocol bounds) was already recorded by P0.4/P0.5.
- Open question for the architect: none blocking. P2.1 will add the device constants file (backoff, ping interval) that ADR 0002 names for the device side; the codec-adjacent ones (`FRAME_MAX_BYTES`, `LOG_MAX_LINES`) are already in `net.lockney.tabula.core.Constants`.
