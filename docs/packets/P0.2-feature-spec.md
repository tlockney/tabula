This is a spec-side packet. A context that executes it must not write code in this repository afterwards.

## Why

Every build-side packet needs a description of the behavior to build. This packet writes `docs/FEATURES.md`, the only bridge between the spec side and the build side.

## Read first

- `AGENTS.md` (clean-room rules, public framing)
- `docs/PLAN.md` sections 2 (clean-room discipline) and 4 (scope)
- The spec-side brief, handed to the executor separately. It is not in this repository and must never be added to it.

## Do

1. Write `docs/FEATURES.md`: one entry per in-scope behavior (plan section 4), each with a stable ID such as `F-SCR-03` and the behavior described in our own words.
2. Include no constants (timeouts, ports, thresholds, defaults). The architect chooses those in ADR 0002.
3. List dropped and deferred items only as one-line hooks.
4. Group entries by area so build-side packets can cite them.

## Out of scope

- Any file other than `docs/FEATURES.md`.
- Design decisions; those belong to the architect.

## Done when

- Every in-scope area in plan section 4 has entries with stable IDs.
- No constants appear in `docs/FEATURES.md`.
- `make check` passes.
- No source paths or names of the spec-side material appear in the repository or in this issue.
