# P5.4 — Log viewer and live log stream

Side: build   Tier: standard   Depends on: P5.1, P5.2
Verification: hardware
Issue: #152
Status: awaiting-hardware

## Why

The protocol has carried a log subscription since P0.4 (`command_log_subscription`, the `log` frame, `LOG_MAX_LINES`/`LOG_MIN_INTERVAL`/`LOG_SUBSCRIPTION_TTL` in ADR 0002) and the integration already accepts `tabula/log` frames into a 200-line deque — but nothing on the device produces them, and nothing displays them. F-MGT-06 asks for the app log and the dashboard's JavaScript console, bounded and streamed live in the Tabularium. This packet closes the loop: a bounded device-side buffer fed by the app's own logging and the WebView console, batching under the protocol's limits, an admin-only panel stream that starts and stops the subscription, and the panel view.

The device part is why this packet needs hardware: console capture and app-log coverage cannot be observed from CI, and the redaction rule is a security property that deserves a run on the tablet.

## Do

1. **Constant.** Add `LOG_BUFFER_LINES = 2000` (per device, in HA's buffer and on the device) and `LOG_VIEW_MAX_LINES = 500` (rendered in the panel) to ADR 0002 and `const.py`/the panel, replacing the ad-hoc `deque(maxlen=200)`; the protocol's per-frame limits stay as they are. State the memory bound in the ADR row.
2. **Device log buffer.** Add a pure-Kotlin bounded ring buffer (`android/core/…/log/LogBuffer.kt`) holding `LOG_BUFFER_LINES` lines: timestamp, level, tag, message, oldest dropped first. Add the redaction filter there (PROTOCOL 4.8: `Authorization` headers, `access_token=`, `authSig=`, `refresh_token` values, query strings stripped from URLs) and test it directly. Keep it free of Android APIs so it is JVM-testable.
3. **App logging facade.** Add an Android sink used by `android/app` and `android/ha` that writes to `android.util.Log` and to the buffer, and replace the direct `Log.*` calls in those modules with it so the stream actually contains the app's log. `android/core` keeps no logging. Prove the sweep with a grep in the Result (no direct `android.util.Log` outside the sink).
4. **Console capture.** `DashboardView`'s `Console` appends each WebView console message to the same buffer with tag `console`, its level mapped from the message level (verbose/debug → debug, warn → warning, error → error). Message and source line, no page URLs with query strings.
5. **Subscription command.** Implement `log_subscription` in the device: while enabled, flush at most every `LOG_MIN_INTERVAL` and at most `LOG_MAX_LINES` per frame, only when there are new lines; an optional minimum level filters at the source; disable stops flushing; the device stops by itself after `LOG_SUBSCRIPTION_TTL` without a refresh. A subscription survives nothing: it ends on reconnect.
6. **Integration.** Keep the ring per device (bounded, newest last, ordered by arrival). Accept `tabula/log` frames as today. Add admin-only panel commands: `tabula/panel_logs` (snapshot: buffered lines, subscription state, whether the device is online, buffer capacity) and `tabula/panel_logs_subscribe` (`enabled`, optional `level`) which sends the `log_subscription` command, relays new lines to the panel over HA's subscription mechanism, refreshes the TTL while at least one panel subscription is open, and sends `{enabled: false}` on the last unsubscribe or when the panel socket closes. A second viewer on the same device shares one device subscription (reference counted). Lines are never written to HA's log or diagnostics by the integration.
7. **Panel view.** The device page's Logs tab: newest-first or oldest-first toggle, level and tag filters, text search, follow/pause (pausing keeps buffering), a streaming indicator with the subscription expiry, clear (view only, not the device buffer), download as a text file, and a bounded DOM (`LOG_VIEW_MAX_LINES`, oldest dropped) so a long tail cannot freeze the browser. Offline device: show the buffered lines with a clear "last seen" note and disable streaming. Console lines are visually distinct from app lines.
8. **Mock device.** Handle `log_subscription` (emit a few lines, honour the interval and the level filter) so the conformance suite covers subscribe/stream/stop and the integration tests run the panel command end to end.
9. **Tests.** Android JVM: buffer bound and order, redaction cases, batching interval and size, level filter, subscription stop and TTL. Python (`integration/tests/test_panel_logs.py`): snapshot bound and order; subscribe sends the command; unsubscribing the last viewer disables it; a panel disconnect cleans up; TTL refresh; admin-only and unknown device; a `tabula/log` frame still validates. TypeScript: filters, follow/pause, DOM bound, offline and empty states. Mock conformance: subscribe/stream/stop.
10. **Device check.** `tools/device/check_p54.sh` and a `docs/DEVICE.md` section (the P3.13 pattern): with the tablet paired and the integration running, open the panel (or drive the same command over the HA WebSocket), confirm app lines and a dashboard console line (`console.log` injected through the dashboard, or an error the dashboard raises) arrive within `LOG_MIN_INTERVAL`+frame latency, that stopping the subscription stops them, and that a request with an `Authorization` header in it does not show the token. ### What changed

- **Constants.** `LOG_BUFFER_LINES = 2000` and `LOG_VIEW_MAX_LINES = 500` in ADR 0002
  (with the memory bound), `const.py`, `android/core/Constants.kt` and the panel
  module; the ad-hoc `deque(maxlen=200)` is gone. PROTOCOL 4.8's per-frame limits are
  untouched.
- **Device ring.** `android/core/…/log/LogBuffer.kt`: bounded, oldest dropped first,
  sequence-numbered so a tail knows what it has sent, timestamps as RFC 3339, tag and
  message cut to the schema's bounds. No Android API.
- **Redaction.** `Redaction.kt`: `Authorization` (any scheme word), `access_token=`,
  `authSig=`, `refresh_token` values, and query strings stripped from URLs and
  absolute paths. Applied at the ring's only entry point, so nothing unredacted can
  be read back out.
- **Subscription rules.** `LogStreamer.kt`: at most one batch per `LOG_MIN_INTERVAL`,
  at most `LOG_MAX_LINES` per batch, only when something new, a minimum level that
  filters at the source, and the TTL stop with no refresh. A fresh enable starts at
  the ring's end (the panel shows HA's buffer, so a replay would duplicate it); a
  repeat enable is a refresh and keeps the cursor.
- **App sink.** `TabulaLog` is now the only caller of `android.util.Log` in the app:
  every line also enters the ring, and `DashboardView.Console` feeds the WebView
  console through it with the `console` tag. `:ha` has no logging of its own (`0`
  call sites before and after), so nothing to sweep there.
- **Command and wire.** `TabulaCommands` handles `log_subscription` through
  `LogStream`, `onNewConnection` ends any subscription, `TlpClient` drains a `logs`
  channel with a `logLoop`, and the app declares the `logs` capability.
- **Integration.** `logs.py`: HA's per-device ring at `LOG_BUFFER_LINES`,
  admin-only `tabula/panel_logs` (buffer, capacity, connection, subscription state)
  and `tabula/panel_logs_subscribe` (reference counted: first viewer starts the
  device subscription, a second viewer shares it, the last unsubscribe or a panel
  socket closing stops it, and the TTL is refreshed while anyone watches). A device
  dropping tells the open streams the subscription is off. Lines are never written
  to HA's log or diagnostics.
- **Panel.** `panel/src/logs.ts`: the Logs tab, newest/oldest toggle, level, tag and
  text filters, follow/pause with a held buffer, a streaming indicator with the
  expiry, clear (the view only), a text download, and a DOM bounded at
  `LOG_VIEW_MAX_LINES`. Console lines carry their own class. `shell.ts` gains three
  lines to route the tab; everything else is the module's own.
- **Mock device.** `log_level` with the filter applied at `log()`, a line written when
  a subscription starts, queued lines dropped when one stops, and the level reset on
  a new connection.
- **Device check.** `tools/device/ha_logs.py` (devices/snapshot/stream over the same
  panel commands the Tabularium uses) and `tools/device/check_p54.sh` driving
  `tabula.navigate` (app line, console line, a URL carrying a token that must not
  appear in the log, a stop, and the buffer bound), plus the DEVICE.md section.

### Deviations and decisions

- **Console line source.** `ConsoleMessage.messageLevel()` gives Chromium's
  `TIP`/`LOG`/`DEBUG`/`WARNING`/`ERROR`; `TIP` maps to debug like `LOG`, so the four
  wire levels lose the distinction between a hint and a log line.
- **Panel unsubscribe keyed by connection, not message id.** An `enabled: false`
  arrives as a new HA message (ids must increase), so it cannot carry the subscribe's
  id; one log stream per panel socket is therefore the rule, documented in
  `logs.py`.
- **The TTL refresh is asserted at the schedule level** in the Python suite
  (`cancel_refresh` set while a viewer is open, cleared when the last leaves), not by
  firing HA's timer: the send it performs is the same `_async_enable` the subscribe
  test covers end to end, and the device-side expiry is covered by the Kotlin TTL
  test.
- **The device check's console line** comes from navigating to a path the frontend
  cannot render; a frontend build that reports a bad route only in the network panel
  would need the verifier to make the console log an error, which the script says.

### Review fixes

The independent review merged `main` (the settings editor landed first, so the
panel shell and `panel_api.async_register` carry both features' routes and
commands) and fixed four things in commits of their own:

- The device page's tab test expected the placeholder on the settings tab;
  settings and logs both have views now, so it checks settings, logs and then
  the activity tab's placeholder.
- A second panel viewer whose level differed from the first left the device
  filtering at the older floor while the stream reported the new level. The
  command is sent whenever the level changes, widening included, with a test.
- A device drop turned the subscription off but left HA's subscription open, so
  the view still held its unsubscribe and the Start button sent nothing. The
  old stream is dropped before a new one is asked for, with a test.
- The logs view's classes had no rules in `styles.css`: the tail could not
  scroll in its own box and console lines were not visually distinct, which is
  the packet's own item. The block is added.
