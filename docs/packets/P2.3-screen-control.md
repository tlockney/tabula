# P2.3 — Screen control

Side: build   Tier: standard   Depends on: P2.1, P1.4
Verification: hardware
Issue: #17
Status: awaiting-hardware

## Why

HA controls the panel through the standard light entity, and adaptive brightness keeps working when HA is down.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 5.5 (brightness ownership) and 7.3 (P2.3)
- `docs/decisions/0002-constants.md`
- `docs/DEVICE.md`
- `android/`

## Do

1. Brightness via `WRITE_SETTINGS`, with a window-dimming fallback.
2. Keep-on wake lock; panel off/on via device-admin lock and wake.
3. Adaptive brightness from the light sensor using a curve we design (JVM-tested), and the brightness ownership rule.
4. Write the hardware check as a script in `tools/device/`.

## Out of scope

- Screensaver (P2.4).

## Done when

- CI: `make check` passes, with unit tests for the curve and ownership rule.
- Hardware (pasted by the hardware verifier): the HA light entity controls the real panel; adaptive brightness keeps working with the network down; a manual change turns adaptive off.
- `PROVENANCE.md` updated.

## Hand back

Result section: CI output; `awaiting-hardware` when the CI part is done.

## Result

### What was built

- `android/core`, `net.lockney.tabula.core.screen` (plain JVM):
  - `BrightnessCurve`: a monotone cubic (Fritsch-Carlson) on a log10 lux axis, with end clamping, inverted curves allowed, and the default points from ADR 0002 `BRIGHTNESS_CURVE`.
  - `ScreenController`: the ownership rule, the change threshold and minimum interval with recheck, the fade steps, and the percent to 0-255 mapping.
- `android/app`:
  - `ScreenManager`: carries out decisions, runs fades with generation-ordered writes, persists screen settings and publishes state.
  - `AndroidPanel`: WRITE_SETTINGS backlight with the window-dim fallback, device-admin `lockNow`, wake on, and screen on/off broadcasts.
  - `LightSensor`, `ScreenAdminReceiver` (force-lock only) and `ScreenWindow` (keep-on flag, window brightness, clearing a swipe-only lock screen).
  - `TabulaCommands` handles `screen` and hands `set_settings` to screen control.
  - The service declares `screen` and `brightness`, plus `adaptive_brightness` when the tablet has a light sensor.
- `integration`: the screen light also writes `screen.brightness` and `adaptive_brightness: false` to HA's settings store as one revision, through the new `settings.async_set_settings` (ADR 0011 item 1).
- Docs:
  - ADR 0011, and the ADR 0002 "Screen control" constants.
  - DEVICE.md hardware check section, and `tools/device/check_p23.sh`.
  - PROVENANCE rows.
- Not built:
  - curve settings and the HA-entity sensor source (F-SCR-05, F-SCR-06);
  - F-SCR-07's curve rescaling for the panel and the JS bridge;
  - F-SCR-09, which needs the P2.4 screensaver.

  ADR 0011 lists these as follow-ups.
