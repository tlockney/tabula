# P3.14 — Screensaver engine polish: pixel shift, fade, dim level

Side: build   Tier: standard   Depends on: P3.1
Verification: hardware
Issue: #72
Status: awaiting-hardware

## Why

ADR 0013 tagged three engine follow-ups as Phase 3 that no other packet picked up: pixel shift (F-SSV-22), the screensaver fade (F-SSV-23) and a separate dim level (F-SSV-07, F-SSV-17) — dim currently borrows `screensaver.brightness` because the schema had no key of its own (ADR 0013 item 4). P3.1's schema v2 carries `screensaver.dim_brightness`, `screensaver.pixel_shift` and `screensaver.fade`; this packet implements all three on the existing `ScreensaverController`/`ScreensaverView` engine. It closes the ADR 0013 follow-up list's Phase 3 remainder.

## Do

1. Pixel shift (F-SSV-22): periodic small shifts of the screensaver content by the configured amplitude and interval, never applied in black mode; the shift wraps so content never leaves a margin at the panel edge. Constants (amplitude bound, interval) come from the ADR 0002 extension.
2. Fade (F-SSV-23): optional fade in on start and out on dismissal of the overlay; modes that show the live page itself (dim, and the HA dashboard view when it ever ships) and web content (the P3.10 website view) switch without a fade. The fade duration is a constant in ADR 0002.
3. Dim level (F-SSV-07): dim mode holds the panel at `screensaver.dim_brightness` instead of `screensaver.brightness` (ADR 0013 item 4); the rest of the brightness-ownership behavior (state reporting, restore on dismissal) is unchanged. Note in the Result that this resolves ADR 0013's "separate dim level" follow-up.
4. JVM tests: pixel-shift stepping (interval, amplitude, no shift in black mode), fade state (start/dismiss transitions, live-page and web-content exemption), dim holding the dim level and restoring correctly around the existing override paths.
5. `tools/device/check_p314.sh` and a DEVICE.md section (it can share a device session with #18's pending run).
6. `PROVENANCE.md` rows.

## Out of scope

- F-SSV-19/F-SSV-20 (panel off after a while, wake behavior).
- Pixel shift or fade for anything but the screensaver overlay.
- Notification brightening (F-SSV-17's temporary brightenings — a separate follow-up).

## Result

Status: awaiting-hardware. CI part done; the hardware part runs
`tools/device/check_p314.sh` (docs/DEVICE.md, "Hardware check (P3.14)").

Built:

- **Pixel shift (F-SSV-22).** `PixelShift` (core) cycles eight offsets one
  amplitude from rest, clockwise from the top, wrapping with floorMod — no
  drift, every step moves content, each axis within ±amplitude, so content
  oversized once by the amplitude never bares the panel edge. Black never
  shifts; dim draws nothing. The clock view moves inside the overlay; the
  gallery moves one container (blur, scrim, slides, details) oversized by
  the amplitude via negative margins while a shift runs. Settings are read
  each time the screensaver starts (ADR 0016 item 8's cadence).
- **Fade (F-SSV-23).** `FadeRule` (core) fades in on start and out on
  dismissal for every overlay Tabula draws itself (clock, black, photos,
  weather, and an unbuilt mode's clock stand-in); the live page itself
  (dim, the HA dashboard view) and web content (website view) switch at
  once. The fade is an alpha animation, `SCREENSAVER_FADE_MS` = 800 ms
  (ADR 0002, new row). The gallery's fade-out keeps the last slide until
  the fade ends; the engine stops and the bitmaps release then.
- **Dim level (F-SSV-07).** `ScreensaverController` holds the panel at
  `screensaver.dim_brightness` while dim shows — resolving ADR 0013 item
  4's "separate dim level" follow-up — with black's lowest level and the
  brightness_enabled behavior unchanged; dismissal still restores the
  previous level (verified by the manager test's `held` list).

Deviations and design notes (recorded in ADR 0022):

- The fade also applies to photos mode: the gallery is one of the
  screensaver's own overlays, so fading it in and out is the same rule;
  only the live page and web content are exempt (F-SSV-23's own carve-out).
- ADR numbering: 0022 was the next free number (main has 0019; open PRs
  hold 0018, 0020, 0021, checked with `gh pr list` + `git ls-tree` per
  branch).
