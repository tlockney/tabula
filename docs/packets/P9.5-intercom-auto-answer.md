# P9.5 — Intercom auto-answer settings

Side: build   Tier: standard   Depends on: P9.3
Verification: hardware
Issue: #143
Status: ready

## Why

Hands-free reaching a person is the reason intercom exists (ADR 0025), and that needs a tablet that answers itself. It is also the riskiest part: a microphone opens without a tap. ADR 0028 narrowed the rule after the house heard feedback: auto-answer may only answer a call that a person or a schedule asked for, and the default stays off.

## Do

1. New settings group `intercom` with `auto_answer` (`off`, `listed`, `all`; default `off`) and `auto_answer_from` (list of device ids, used by `listed`). Adding keys bumps the settings schema: freeze the current version, add the down-translation, regenerate Kotlin settings, extend the options flow and entities exactly as P7.1 did for `voice`. If another open packet has already bumped the schema, rebase and take the next version number.
2. Engine behavior: on a ring that matches the setting, answer without a tap after a short tone on the communication stream (ADR 0028), then show the in-call banner (P9.4) for the whole call. Never auto-answer a broadcast with the microphone open, and never when the ring did not come from an explicit HA service call or device-screen request (guard 1); a ring carries its origin so the device can check.
3. Auto-answer never applies while `intercom_talk` is not declared (listen-only still receives).
4. Tests: every setting value against every ring origin and mode, the tone-before-open ordering with a fake clock and fake audio, the settings migration both ways, options flow validation (a `listed` setting with an empty list is rejected).
5. `docs/provenance/P9.5.md`: independent design; note the default-off decision.

## Out of scope

Schedules that turn auto-answer on at certain times (later packet), the engine, UI changes beyond what the setting needs.

## Done when

- `make check` and the Android unit-test target pass; output pasted.
- Device part (hardware verifier, owner-scheduled): auto-answer from a listed device and a refusal from an unlisted one. Set `awaiting-hardware`.

## Hand back

Result: pasted output, schema version used, deviations. Add `needs-review` with the head SHA; ask for a second independent reviewer (opens a microphone without a tap).

The four production guards from ADR 0028 are requirements, not options: (1) a call starts or is answered only through an explicit action or a schedule, never because a device is online; (2) a hard call time limit; (3) `tabula.intercom_end` reaches every device in the call in every call state; (4) no call resumes after a device restarts.

Audio rule (owner, binding): no test, script or run in this packet plays or captures audio on a household device unless the owner schedules it. Silent analysis, unit tests and CI are fine. Do not run `tools/device/check_p90*.sh`, `check_p70.sh` or set `TABULA_AUDIO_OK`.
