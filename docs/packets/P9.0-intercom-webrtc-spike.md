# P9.0 — Intercom spike: native WebRTC audio between devices

Side: build   Tier: deep   Depends on: none (uses P7.0's mic-persistence findings when available)   Timebox: 3 working days
Verification: hardware
Issue: #27
Status: awaiting-hardware

## Why

ADR 0025 makes intercom the first-priority feature: two-way calls with optional auto-answer, one-way live broadcast, audio directly between devices over a native WebRTC library, HA as directory and signaling path. Before any production code, this spike shows that the library runs on each v1 device type, that echo cancellation makes hands-free calls usable on tablet speakers, and what it costs.

## Questions to answer, with evidence

Use two devices. Run on two Fire HD 10 Plus units, and on an Echo Show 8 paired with a Fire HD if the Echo Show is in v1 at the time.

1. **Library.** Which Maven Central WebRTC Android artifact (for example `io.github.webrtc-sdk:android`) resolves through the project's Gradle setup, supports minSdk 24 and runs on API 28? Its license, version, and APK size added per ABI.
2. **Connection.** Two devices connect audio-only with host candidates on the LAN and no STUN or TURN server, with offer, answer and candidates passed by hand or through a throwaway relay. Time from offer to first audio.
3. **Hands-free quality.** Full-duplex call at normal speaking volume, speakers at a usable level, people 1 m and 3 m from each device. Does the library's echo cancellation stop the far end hearing itself? Record a short clip from each end. Also record the case of two devices in the same room.
4. **Background and screen states.** Does the call keep working with the dashboard, a screensaver or another app in front, and with the panel off? Does a call start from the foreground service while the app is not in front?
5. **Listen-only.** With `RECORD_AUDIO` revoked (the Fire OS case from P7.0), can the device still receive and play a call?
6. **Broadcast.** One sender to two receivers, one-way. CPU on the sender.
7. **Cost.** CPU, memory and heat during a 10-minute call on each device type. Latency mouth to ear, rough (clap test).

### What was built and how it was run

A debug-only spike application, `net.lockney.tabula.spike.intercom`, in its own Gradle module
(`android/spike-intercom/`, ADR 0028). Its own applicationId and a disabled release variant mean
installing it cannot replace, uninstall or unpair `net.lockney.tabula`; the automated run prints
both packages installed side by side on both tablets. Signaling is a throwaway stdlib HTTP relay on
the LAN (`tools/device/intercom_relay.py`) because TLP signaling does not exist yet; no STUN or
TURN server is configured anywhere.

Two Fire HD 10 Plus units (KFTRPWI, Fire OS 7 / API 28, arm64-v8a): the Office Kiosk calling, the
Desk Kiosk answering. `tools/device/check_p90.sh` places the calls itself
(`am start-foreground-service`, so no app is in front), streams both devices' `TabulaIntercomSpike`
logcat to files, and prints the evidence below. `tools/device/intercom_report.py` turns those two
logs into the connection, media and mouth-to-ear figures.

### The verifier's part

**Audio checks are opt-in.** These scripts make a tablet listen and speak in the room it lives in,
so they refuse to run unless `TABULA_AUDIO_OK=1` is set, and that variable is only ever set for a
run the owner has scheduled. The commands below are for that session; do not set it otherwise, and
do not leave it exported in a shell that does other work.

Run from an interactive shell, only in an owner-scheduled session. It places a 6-minute call itself
and asks what you hear.

```
TABULA_AUDIO_OK=1 TABULA_HOST_IP=<the Mac's LAN address> tools/device/check_p90_owner.sh
```

1. Stand 1 m from the Office Kiosk, speak normally, then listen at the Desk Kiosk: intelligible at
   normal volume? Did the far end hear itself, or howl?
2. The same at 3 m.
3. Move both tablets into one room, 1 m apart, speakers facing away from each other, and speak at
   one: any runaway feedback?
4. Clap once, loudly, 1 m from the Office Kiosk's microphone: at the Desk Kiosk, did it arrive
   without a noticeable delay (under about a tenth of a second)?

Step 3 is the case that already happened by accident: a two-way call between the two tablets in this
house produced sustained feedback the occupants heard. Expect it, and note how quickly it can be
stopped.

3 m, whether the far end hears itself in a normal call, and whether the clap arrives without a

### Deviations and notes

- **Broadcast (question 6) is not measured, needs an owner-scheduled run.** Two tablets existed; a
  third was not available, and the run has to be scheduled with the owner.
- **The 10-minute cost and the mouth-to-ear clap judgment are not measured, needs an
  owner-scheduled run.** `check_p90_cost.sh` got 90 s of its 600 s before the caller dropped off
  ADB; the three samples are pasted above and nothing is extrapolated from them. No ten-minute cost
  figure is quoted anywhere in this packet or in ADR 0028.
- **The Echo Show 8 is unmeasured.** It is in v1 (ADR 0026) but no unit has been through P2.7's
  bring-up, so there was nothing to install on. ADR 0028 leaves its verdict to P2.7.
- **A real two-way call in the house produced sustained acoustic feedback.** Both tablets had
  software echo cancellation on; each cancels only its own speaker, so the loop closed anyway and
  the people in the house heard it. This is the packet's most important result: the library and the
  audio path work, and hands-free use needs guards. ADR 0028 records the four production
  requirements (explicit per-call action or schedule, a hard call time limit, an HA way to end every
  call, no auto-resume after reboot) and narrows ADR 0025 decision 1's auto-answer to a call that a
  person or a schedule asked for.
- **Audio device checks are opt-in.** `check_p90.sh`, `check_p90_owner.sh` and `check_p90_cost.sh`
  exit 2 unless `TABULA_AUDIO_OK=1` is set, with a message that audio device tests must be scheduled
  with the owner. Same guard style as P7.0's `check_p70.sh` and `check_p25.sh`. The variable is set
  only in an owner-scheduled session, never by an agent. The cost script was named
  `check_p90_cost.sh` until this review: P7.0's guard meta-test globs `check_*.sh` and keeps its own
  list of audio scripts, so a name outside that glob left the guard unenforced.
- **Merge order for P7.0's guard test.** `tools/tests/test_device_scripts.py` (P7.0, PR #132) fails
  if an audio script is missing from its `AUDIO_SCRIPTS` list, and its list names only `check_p25.sh`
  and `check_p70.sh`. This branch cannot edit that file — it does not exist here — so whichever pull
  request merges second adds `check_p90.sh`, `check_p90_owner.sh` and `check_p90_cost.sh` to
  `AUDIO_SCRIPTS`. The guard text itself is already identical, so the test's exit-2 and message
  assertions pass once the three names are listed.
- **The audio-effect claims stop where the pasted output stops.** The pasted lines establish that
  neither unit has a hardware canceller or suppressor and that the software path was switched off
  and on as the runs asked. They do not measure what the software canceller removes, so ADR 0028
  claims no cancellation figure.
- **The Desk Kiosk dropped off ADB twice during the session.** Both times it came back within a
  minute and the checks were re-run; the likely cause is the parallel P7.0 voice spike rebooting
  it for its mic-persistence test. Nothing of the voice spike's `.spike.voice` app was touched, and
  no mic contention was observed in this run's logs (the spike is the only microphone client while
  a call is up).
- **`dumpsys cpuinfo` was not credible for the app's own CPU on this device.** It gave the two
  kiosks figures that contradicted each other inside the same call, so `check_p90_cost.sh` measures
  the app from `/proc/<pid>/stat` against `/proc/stat` over a 5 s window and keeps dumpsys's device
  TOTAL and audio-HAL figures as a cross-check. Fire OS also answers "Error: Not found; no service
  started." for a few seconds after an install or reboot while the package manager settles, so
  `intercom_devices.sh` grew a `start_service` retry; without it a long measurement dies on the
  first sample.
- **ADR number:** 0028 is free. Checked on `main` (which tops out at 0027) and across the open pull
  requests when this was written: P7.0 (#132) takes 0029, and no other open pull request adds an ADR.
