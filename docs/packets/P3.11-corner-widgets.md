# P3.11 — Corner widgets

Side: build   Tier: standard   Depends on: P3.5, P3.6
Verification: hardware
Issue: #69
Status: ready

## Why

F-WGT-01 to F-WGT-06 and F-WGT-09: small overlays anchored to the four screen corners — a small clock, weather, forecast, battery and a single-entity widget. The next-alarm (F-WGT-07) and up-next (F-WGT-08) widgets wait for alarms and calendar (Phase 6). The HA-backed widgets consume the P3.5 entity data connection, and the icon infra and pill conventions come from P3.6.

## Do

1. The widget layer (F-WGT-01): at most one widget per corner; each individually disabled without losing its corner; a global switch hides all (P3.2's `widgets shown` entity drives it); draws over all modes except calendar (not built) and the black mode's hide-everything option; global scale, per-widget relative scale, global font with per-widget override, optional text shadow, adjustable dark vignette.
2. Small clock widget (F-WGT-03): time with optional date, 12/24-hour, color; never shown over the clock mode.
3. Weather widget (F-WGT-04): place name, temperature (actual, apparent, or both when they differ), condition with icon, humidity, wind, visibility; missing lines hidden; sunny/partly-cloudy icons switch to night variants after sunset (sun entity, local-time fallback); condition names in HA's translations; live while the screensaver runs; last values kept through brief disconnects; hidden until an entity is chosen.
4. Forecast widget (F-WGT-05): one row per day (day name, condition icon, high, low) from the entity's daily forecast via P3.5's forecast access; days and include-today options; nothing if there is no daily forecast; lows omitted if only highs exist.
5. Battery widget (F-WGT-06): from the device directly (offline): icon, charging indicator, optional percentage, optional only-when-low; hidden on devices without a battery.
6. Entity widget (F-WGT-09): icon, value (state or chosen attribute), optional custom name, optional visibility-by-value list (case-insensitive); disappears when the value is empty; unknown/unavailable still show; formatting as F-AAG-03.
7. Night mode via the `NightState` interface pre-committed by P3.1's ADR 0002 extension (never-night default; P3.4 implements it whenever it lands): it is observable — a listener registration whose callback carries each transition — so the widgets re-render when night changes; all widgets use the night color; the hide-overlays option hides them.
8. Corner priority over the photo details overlay (F-WGT-02): the details overlay moves to a free corner.
9. JVM tests with a fake entity feed and fake battery: corner assignment, disable-without-reassignment, night behavior, each widget's line/visibility rules, mode exclusions.
10. `tools/device/check_p311.sh` and a DEVICE.md section.
11. `PROVENANCE.md` rows.

## Out of scope

- Next-alarm and up-next widgets (Phase 6).
- Widget taps opening views (alarm list, calendar) — the targets do not exist yet.
- Any new screensaver mode or the schedule.
