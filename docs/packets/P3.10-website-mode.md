# P3.10 — Website screensaver mode

Side: build   Tier: standard   Depends on: P3.1, #16 (or a timeboxed spike)
Verification: hardware
Issue: #68
Status: ready

## Why

F-SSV-13 and F-SSV-14: a full-screen web view of any URL, sharing the dashboard's cookies, with its own zoom; pages on the configured HA server are authenticated with the dashboard session and shown without HA's header and sidebar; failed loads retry on an interval instead of showing an error page; an option makes dismissal require a double tap so single taps reach the page.

Unverified device fact this packet depends on: the dashboard WebView has not been observed on the tablet — P2.2's hardware part (#16) is still awaiting-hardware, and website mode builds on the same external-auth, cookie and link-handling machinery. Either wait for #16's device run (both checks can share one session) or start with a timeboxed on-device spike that confirms the P2.2 behaviors website mode extends.

## Do

1. Timeboxed gate first (timebox: 1 working day): run P2.2's `check_p22.sh` if #16 has not closed, or fold both into one device session. If the P2.2 device run surfaces problems with external auth or link handling on the real WebView, hand back rather than build on sand.
2. The website view: a second WebView instance sharing the cookie store, with its own zoom setting; loads the configured URL when the screensaver starts in this mode; no error page — a failed load or server error retries on an interval (constant in ADR 0002) with the previous content kept meanwhile.
3. HA-origin pages: authenticated with the dashboard session, and shown without HA's header and sidebar. The hiding mechanism needs a design decision recorded in an ADR — a supported frontend lever only (no patching of frontend internals; the plan's entity-filter warning applies to DOM hiding too). If no supported lever exists for HA pages, ship external pages unchanged and the HA-page hiding becomes a documented gap in the ADR rather than a hack.
4. Dismissal: single tap dismisses by default; with the double-tap option on, only a double tap leaves and single taps reach the page (F-SSV-14). Touch does not dismiss on the first tap of a double tap.
5. Pause/resume and lifecycle: the mode keeps the dashboard underneath alone (F-SSV-25's pause optimization is Phase 4 and explicitly out of scope); the website view is torn down on dismissal.
6. JVM tests: retry-on-failure logic with a fake loader, double-tap detection, HA-origin classification (reuse `DashboardLinks`'s origin rules), zoom handling.
7. `tools/device/check_p310.sh` and a DEVICE.md section.
8. `PROVENANCE.md` rows.

- WebView pausing/hiding optimization (Phase 4).
- The plugin bridge on website pages.
