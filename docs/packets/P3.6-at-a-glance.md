# P3.6 — At a Glance row

Side: build   Tier: standard   Depends on: P3.5
Verification: hardware
Issue: #64
Status: awaiting-hardware

## Why

F-AAG-01 to F-AAG-04: a row of a few entity states drawn on the screensaver for checking things in passing — doors, locks, garage. It is the first consumer of the P3.5 entity data connection, and it introduces the on-device rendering of HA icons, which the weather/forecast/entity widgets (P3.11) reuse.

Night mode is consumed through the `NightState` interface pre-committed by P3.1's ADR 0002 extension (never-night default), so this packet does not wait on P3.4's hardware-dependent spike; whichever of P3.4 and P3.6 merges last wires the real flag.

## Do

1. Icon rendering, decided in an ADR first: how a device renders an HA entity's icon (`mdi:…`) offline. The Companion app bundles the MDI font; if Tabula bundles it, record the font's license and attribution. The fallback (no icon: the domain's initial) must be defined.
2. The row (F-AAG-01): user-defined order from the settings list, placement per mode (centered on black, under the date on the clock, near the bottom over photos/website later), wrap onto two lines in portrait, text shrinking before name truncation, not drawn on the calendar mode (not built yet; the exclusion still lands now).
3. Appearance (F-AAG-02): icon, name, value; contrasting pill unless the plain style is chosen; icon background reflects active/inactive state as HA tiles do; text color never changes with state; hide-names, monochrome-icons, scale, font options.
4. Formatting (F-AAG-03): HA icon if set else the domain default; states capitalized as HA presents them; numeric states rounded to HA's display precision with unit; empty values drop out; unknown/unavailable still show.
5. Night mode: consume the `NightState` interface pre-committed by P3.1's ADR 0002 extension (never-night default). It is observable — a listener registration whose callback carries each transition — so the row re-renders when night changes instead of re-reading the flag per frame; the row hides when night is active and the hide-overlays option says so, and otherwise uses the night color. Whichever of P3.4 and P3.6 merges last wires the real flag; the never-night default keeps the row honest until then.
6. JVM tests with a fake entity feed: ordering, placement, formatting, drop-out, unavailable, night behavior.
7. `tools/device/check_p36.sh` and a DEVICE.md section.
8. `PROVENANCE.md` rows.

## Result

**What changed**

- Icon rendering, ADR 0032: no icon font is bundled. A curated vector glyph set
  (lock, unlock, door, garage, light, power, motion, thermometer, battery,
  water, alert) is drawn with Canvas paths on a unit box, keyed by the `mdi:`
  name HA would show, falling back to the entity domain's glyph and then to the
  domain's initial. `GlanceIcons` holds both tables and is plain JVM.
- `android/core/.../screensaver/glance/Glance.kt`: `GlanceValue`, `GlanceChip`,
  `GlanceGlyph`, `GlancePlacement`, `GlanceMetrics` and `AtAGlanceRow`, the
  planner. It orders chips by `at_a_glance.entities`, drops empty values, caps at
  `GLANCE_MAX_CHIPS`, places per mode (clock under the date, black centered,
  photos/website/weather/dashboard bottom, **dim and calendar never**), wraps to
  two lines in portrait, fits by shrink (100 % down to 75 % in 5 % steps) and
  only then truncates names with an ellipsis, reporting any dropped tail as
  `omitted`. Night and `hide_overlays` are inputs, not lookups.
- `android/ha/.../GlanceFeed.kt`: live states plus `DisplayData` to the row's
  values. The name is `friendly_name` else the spaced object id; the value is
  HA's own state text, or the state rounded half-up to the entity's display
  precision with its unit (`21.5 °C`); a blank state stays blank (drops out); a
  missing entity reads `Unavailable`; the icon is HA's; active/inactive follows
  `GLANCE_INACTIVE_STATES` (`locked`, `closed`, `off`, `unknown`, `unavailable`
  and friends are inactive; `unlocked`, `open`, `on` and numbers are active).
- `AtAGlanceView`: the chips. Pill or plain style, the icon box's active/inactive
  fill, the night palette, `hide_names` (larger values), `monochrome_icons`,
  `scale` and `font`; text color never changes with state.
- `ScreensaverView`: the row as its own overlay child. Placement per mode with
  the clock's date-line offset, the run's pixel shift applied to the row as well,
  a `NightState` listener registered while a run shows and removed on dismissal
  (constructor default `NightState.NEVER`), and one `TabulaGlance` log line per
  render plus one per chip - the hardware check's evidence.
- Wiring: `TabulaStatus.entityStates`/`entityDisplay` published by
  `TabulaService` from P3.5's connection; `MainActivity` feeds the row on every
  state, display-data and settings change, independent of the dashboard page.
- Constants: ADR 0002's new "At a Glance (P3.6)" section and their values in
  `Constants.kt`.
- `tools/device/check_p36.sh` and the DEVICE.md section; `docs/provenance/P3.6.md`.

**Deviations and open questions**

- Night: the row consumes the pre-committed `NightState` and the constructor's
  default stays `NightState.NEVER`, as the packet says; whichever of P3.4 and
  P3.6 merges last wires the real flag. The night step of the hardware check
  therefore runs in P3.4's run, and `check_p36.sh` says so instead of pretending
  to test it.
- Photos/website placement (bottom) is decided in the planner but drawn only
  once P3.7/P3.10 build those modes; the row reaches them through the same call.
- The black mode's hide-everything key (F-SSV-06) still does not exist, so black
  draws the row (centered) and the subscription opens; the key and its gate in
  `EntityNeeds` remain the follow-up ADR 0017 recorded.
- Unit strings are the attribute HA sends, not HA's translated unit names; the
  frontend's unit resources are a later refinement.
- At the shrink floor a row that still does not fit drops its tail chips and logs
  the count (`omitted`), per ADR 0032 item 5.
- Hardware part: awaiting the verifier (`tools/device/check_p36.sh`, DEVICE.md).
