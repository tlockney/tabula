# P2.7 — Echo Show 8 bring-up

Side: build   Tier: standard   Depends on: P0.6 (go), P2.6
Verification: hardware
Issue: #33
Status: ready

## Why

The Echo Show 8 (2nd gen) is a v1 target once P0.6 says it is feasible. Phase 2 is built and accepted on the Fire HD 10 Plus first; this packet makes the same app work on the Echo Show and documents how to provision it. If P0.6 is no-go, this packet is closed as not planned.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 3, 4 and 7.3
- The ADR written by P0.6
- `docs/DEVICE.md`
- `tools/device/`

## Do

1. Provision one Echo Show by following DEVICE.md as written for the Fire HD 10 Plus. Record every step that fails or differs.
2. Add an Echo Show section to DEVICE.md and change the provisioning scripts in `tools/device/` so they handle both device types.
3. Run the P2.1–P2.6 hardware checks on the Echo Show. Fix or file issues for what fails. Expected differences to check: the 1280×800 screen, which sensors exist (adaptive brightness needs a light sensor), how the Alexa home screen interacts with start-on-boot and staying in the foreground, and whether device-admin lock and wake work.
4. Provision the second Echo Show from DEVICE.md alone, without help from the first run's notes.

## Out of scope

- Voice, camera and microphone use (Phase 7 and later).
- Kiosk lockdown (Phase 4).
- Exploits, rooting or firmware changes of any kind.

## Done when

- CI: `make check` passes.
- Hardware (pasted by the hardware verifier): the P2.6 acceptance script passes on the first Echo Show; the second is provisioned from DEVICE.md alone and pairs with HA.

## Hand back

Result section: the list of differences found and how each was handled, script output, and `awaiting-hardware` when the scripts are ready.
