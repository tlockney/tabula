# P2.7 — Echo Show 8 bring-up

Side: build   Tier: standard   Depends on: P0.6 (owner go, ADR 0026), P2.6
Verification: hardware
Issue: #33
Status: ready (waiting on the owner's flash)

## Why

The Echo Show 8 (2nd gen) is a v1 target by the owner's decision (ADR 0026): the owner unlocks the bootloader and flashes the community LineageOS 18.1 (Android 11) image himself, by hand, from the public community guide — agents never drive the exploit. This packet makes the Phase 2 app work on that flashed device and documents how to provision it. It cannot start until the owner has flashed the device; the #33 comment records that wait.

## Do

1. **Device probe first** (hardware verifier, read-only, on the owner-flashed LineageOS device, never on stock firmware): the ADR 0001 item 6 command list, plus:

   ```sh
   adb shell getprop ro.product.device          # expect: athena
   adb shell getprop ro.build.version.release   # expect: 11 (LineageOS 18.1)
   adb shell getenforce                         # expect: Permissive (ADR 0026)
   adb shell wm size
   adb shell wm density
   adb shell dumpsys sensorservice | grep -iE 'light|proximity'
   adb shell pm list features
   adb shell cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN
   ```

   Record the WebView version against the Chromium 67 floor and the answers to ADR 0026's probe questions in the packet's Result. If the device is not yet flashed, stop: the packet waits.
2. Provision one Echo Show by following DEVICE.md as written for the Fire HD 10 Plus. Record every step that fails or differs.
3. Add an Echo Show section to DEVICE.md and change the provisioning scripts in `tools/device/` so they handle both device types.
4. Run the P2.1–P2.6 hardware checks on the Echo Show. Fix or file issues for what fails. Expected differences to check: the 1280×800 screen, which sensors exist (adaptive brightness needs a light sensor), LineageOS launcher behavior against start-on-boot and staying in the foreground, the device-admin lock and wake, and the ADR 0026 properties (permissive SELinux, deep sleep disabled, the mute-as-power button).
5. Provision the second Echo Show from DEVICE.md alone, without help from the first run's notes.

## Out of scope

- The bootloader unlock and the flash themselves: owner-performed, by hand, from the public community guide (ADR 0026). No agent runs, scripts or automates any part of them.
- Voice, camera and microphone use (Phase 7 and later).
- Kiosk lockdown (Phase 4).
- Any further exploit, rooting or firmware changes.

## Done when

- CI: `make check` passes.
- Hardware (pasted by the hardware verifier): the step 1 probe output; the P2.6 acceptance script passes on the first Echo Show; the second is provisioned from DEVICE.md alone and pairs with HA.
