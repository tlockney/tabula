# P7.2 — Voice protocol and mock-device voice capability

Side: build   Tier: deep   Depends on: P7.1
Verification: ci
Issue: #144
Status: in-review

## Why

P7.1 gives HA a wake-word event. Voice turns need audio to reach HA. ADR 0024 decision 2 puts 16 kHz, 16-bit mono PCM on the device's existing HA WebSocket as binary frames, gated by a capability. This packet defines that channel and teaches the mock device to speak it, so P7.3 (the satellite entity) is testable in CI without any microphone.

## Do

1. Capability `voice` (additive, PROTOCOL 8). Commands integration→device: `voice_start` (a turn id, the binary handler id, start stage, optional wake-word phrase) and `voice_stop` (turn id, reason). Events device→integration: `voice_turn_started` (turn id, phrase), `voice_turn_ended` (turn id, reason). State key for the turn state if needed (idle, listening, speaking), minimal.
2. Binary framing: first byte is the HA handler id, the rest PCM 16 kHz 16-bit mono little-endian. Chunk size and limits go in PROTOCOL.md and ADR 0002 (`VOICE_CHUNK_BYTES`, `VOICE_TURN_MAX_S`); derive them from HA's own chunking for `assist_pipeline` (frame size 10 ms or similar, read from HA core) rather than inventing. `FRAME_MAX_BYTES` keeps applying to JSON frames only.
3. Schema, fixtures, `tools/validate_frames.py`, Kotlin codegen as in P7.1 (the codec may carry the binary frame type as a plain byte-array wrapper; the app side stays out of scope).
4. Mock device: declares `voice`, starts a turn on `voice_start`, streams PCM read from a WAV file or generated silence/tone **in memory** (no audio output device is touched), ends on `voice_stop`, the timeout, or disconnect. A test hook starts a turn as if a wake word fired.
5. Tests: framing round trips, the mock's turn state machine, binary and JSON frames interleaved on one connection, turn limit, disconnect mid-turn, capability gating.
6. `docs/provenance/P7.2.md`: independent design.

## Out of scope

The `assist_satellite` entity and pipeline calls (P7.3), any Android capture or playback, wake-word changes.

### Constants (ADR 0002, derivation in ADR 0032)

`VOICE_CHUNK_BYTES` 320 (160 samples at 16 kHz, 16-bit mono, HA's own
`SAMPLES_PER_CHUNK`/`BYTES_PER_CHUNK` in `assist_pipeline/const.py`),
`VOICE_FRAME_INTERVAL` 10 ms (one frame per chunk of real time),
`VOICE_TURN_MAX_S` 300 s (HA's `DEFAULT_PIPELINE_TIMEOUT`), so a lost
`voice_stop` cannot stream forever.

### Wire

`docs/PROTOCOL.md` 4.10: the first byte of a binary message is the HA handler
id, the rest is exactly `VOICE_CHUNK_BYTES` of little-endian PCM; `FRAME_MAX_BYTES`
keeps applying to JSON frames only. Capability `voice`; commands `voice_start`
(`turn_id`, `handler_id`, `start_stage`, optional `wake_word_phrase`) and
`voice_stop` (`turn_id`, `reason`); events `voice_turn_started` (`turn_id`,
optional `phrase`) and `voice_turn_ended` (`turn_id`, `reason`);
state key `voice_turn` (`idle` | `listening`), with speaking staying
`media_state` (ADR 0024).

### What it does

- Schema: `$defs/turn_id`, `$defs/handler_id`, two command frames, two event
  branches, state key, `voice` in the capability enum; five fixtures plus one
  invalid fixture; `tools/validate_frames.py` knows the two shared defs.
- Mock device: declares `voice`; `begin_voice_turn` enforces one turn per
  device (`busy`), the handler byte range and the wake-word/phrase rule; the
  turn ends on `voice_stop`, its own limit (`timeout`) or the connection
  closing (no event). PCM comes from `Silence`, `Tone` or a WAV file held in
  memory — no audio device is opened, played or captured. `TLPClient` paces one
  frame per `VOICE_FRAME_INTERVAL` and sends it as a binary message on the same
  socket, so JSON and binary interleave. `start_wake_word_turn` is the test
  hook for a turn the device starts itself.
- Test server: registers binary handlers the way HA does (lowest free id,
  1–255), records each handler's PCM, counts frames, and treats an unregistered
  handler id or a wrong chunk length as a problem, so a malformed frame fails
  the suite.
- HA: `voice_start`/`voice_stop` in `COMMAND_CAPABILITIES` (capability `voice`),
  both turn events on `tabula_voice`.
- Kotlin: `VoiceFrame` (handler byte + payload, encode/decode, bounds),
  `VoiceStartArgs`, `VoiceStopArgs`, `VoiceTurnStarted`, `VoiceTurnEnded`, the
  three voice enums, the `voice` capability, the two commands in `Tlp.frameTypes`
  and the `voice_turn` state key. The app neither captures nor plays anything
  and does not declare `voice`, so the commands stay out of `Commands.all` and
  still answer `unsupported_command` (4.5).

### Deviations

- PROTOCOL 4.10 says the device enforces `VOICE_TURN_MAX_S` itself; the mock
  does, and reports `voice_turn_ended` with `timeout`. The integration-side
  timeout stays P7.3's.
- The packet allowed the binary frame to be "a plain byte-array wrapper"; it is
  `VoiceFrame` in `:core`, with its own test, because the Android codec had no
  binary type to extend.
- `mockdevice/tests/test_session.py` skips the `command_voice_*` fixtures in the
  blind "send every command fixture" loop: a turn has a lifecycle, so
  `test_voice.py` drives those three fixtures one turn at a time instead.
