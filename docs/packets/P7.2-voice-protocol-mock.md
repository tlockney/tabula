# P7.2 — Voice protocol and mock-device voice capability

Side: build   Tier: deep   Depends on: P7.1
Verification: ci
Issue: #144
Status: ready

## Why

P7.1 gives HA a wake-word event. Voice turns need audio to reach HA. ADR 0024 decision 2 puts 16 kHz, 16-bit mono PCM on the device's existing HA WebSocket as binary frames, gated by a capability. This packet defines that channel and teaches the mock device to speak it, so P7.3 (the satellite entity) is testable in CI without any microphone.

## Do

1. Capability `voice` (additive, PROTOCOL 8). Commands integration→device: `voice_start` (a turn id, the binary handler id, start stage, optional wake-word phrase) and `voice_stop` (turn id, reason). Events device→integration: `voice_turn_started` (turn id, phrase), `voice_turn_ended` (turn id, reason). State key for the turn state if needed (idle, listening, speaking), minimal.
2. Binary framing: first byte is the HA handler id, the rest PCM 16 kHz 16-bit mono little-endian. Chunk size and limits go in PROTOCOL.md and ADR 0002 (`VOICE_CHUNK_BYTES`, `VOICE_TURN_MAX_S`); derive them from HA's own chunking for `assist_pipeline` (frame size 10 ms or similar, read from HA core) rather than inventing. `FRAME_MAX_BYTES` keeps applying to JSON frames only.
3. Schema, fixtures, `tools/validate_frames.py`, Kotlin codegen as in P7.1 (the codec may carry the binary frame type as a plain byte-array wrapper; the app side stays out of scope).
4. Mock device: declares `voice`, starts a turn on `voice_start`, streams PCM read from a WAV file or generated silence/tone **in memory** (no audio output device is touched), ends on `voice_stop`, the timeout, or disconnect. A test hook starts a turn as if a wake word fired.
5. Tests: framing round trips, the mock's turn state machine, binary and JSON frames interleaved on one connection, turn limit, disconnect mid-turn, capability gating.
6. `docs/provenance/P7.2.md`: independent design.

## Out of scope

The `assist_satellite` entity and pipeline calls (P7.3), any Android capture or playback, wake-word changes.

## Done when

- `make check` passes; fixtures validate; mock-device and conformance tests pass; output pasted.
- ADR 0002 lists the voice constants with their derivation.

## Hand back

Result: frames and constants added with derivations, pasted output, deviations. Add `needs-review` with the head SHA; ask for a second independent reviewer (protocol, voice).

Audio rule (owner, binding): no test, script or run in this packet plays or captures audio on a household device unless the owner schedules it. Silent analysis, unit tests and CI are fine. Do not run `tools/device/check_p90*.sh`, `check_p70.sh` or set `TABULA_AUDIO_OK`. The mock device must not open any real audio device.
