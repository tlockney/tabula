# P10.2 — Presence sources and HA presence sensor

Side: build   Tier: deep   Depends on: P3.5
Verification: hardware
Issue: #89
Status: ready (blocked until P3.5 merges)

## Why

F-SSV-24 lets an HA occupancy, motion or presence binary sensor dismiss the screensaver and hold the idle timer. Its "Open" note asks the architect to keep the presence-source abstraction general so device sensors plug in later. Camera presence (P10.3) is the first such device sensor, so this packet builds the abstraction and the HA source together. The HA source reads its entity over the entity data connection from P3.5, not TLP.

## Do

1. Design ADR: a `PresenceSource` interface in plain JVM code (`android/core`) that reports present / absent / unknown with transitions, and one `PresenceRule` that turns source transitions into engine actions. Several sources may be active; state the combining rule (present if any source is present) and keep F-SSV-24's per-screensaver rule: a source already present when a screensaver starts has no effect until it goes absent and present again.
2. Rule behavior (F-SSV-24): a transition to present dismisses the screensaver; present holds the idle timer from expiring; option "dismiss only when the panel is off"; option "postpone while present"; ignored under lockdown (when lockdown exists); the schedule's per-slot presence override (F-SSV-18, already a schema key) is honored.
3. Wake from panel-off: a presence transition while the panel is off (P3.4's night power-off today, F-SSV-19 later) powers it on and lands on the dashboard, the F-SSV-20 default. The screensaver-preserving wake option is out of scope.
4. HA source: settings `presence.ha_entity` (a binary_sensor entity id, empty = off) and the two options; schema bump with migration, an ADR 0002 extension for defaults, options-flow fields and settings entities per ADR 0015. The device subscribes to that one entity through the P3.5 component; `unavailable`/`unknown` map to unknown, which neither dismisses nor holds.
5. Tests: JVM tests for the rule with fake sources and a fake clock (transition dismisses, already-present ignored until re-trigger, hold, panel-off wake, schedule override, dismiss-only-when-off); integration tests for the schema, migration and entities.
6. `tools/device/check_p102.sh` and a DEVICE.md section; `PROVENANCE.md` rows.

## Out of scope

- The camera source (P10.3) and its HA entities (P10.4).
- The screensaver-preserving wake setting (F-SSV-20's configurable part), panel-off-after-a-while (F-SSV-19) itself, lockdown mode (Phase 4).
