# P3.5 — Entity data connection (subscribe_entities)

Side: build   Tier: deep   Depends on: P3.1
Verification: ci
Issue: #63
Status: review

## Why

F-AAG-04: the At a Glance row and the HA-backed widgets subscribe only to their own entities over the device's own HA connection while the screensaver is showing, and unsubscribe when it closes — independent of the dashboard page and of TLP. The weather screensaver (P3.7) and the weather/forecast/entity widgets (P3.11) consume the same component.

Whether that rides the existing TLP socket or a dedicated one is a design decision this packet makes in an ADR — PLAN 5.1 ("One connection, HA owns everything") sanctions nothing of the kind today and is amended by this packet either way. The preferred option is the shared socket: TLP already rides HA's own `/api/websocket`, so `subscribe_entities` is one more HA command on the shared id counter, with no second auth, keepalive, backoff or token-refresh loop. A dedicated socket remains defensible (isolated lifecycle; a slow state burst cannot delay TLP frames) if implementation shows a need.

This packet also settles how the device reads daily forecast data (HA moved weather forecasts off entity attributes; `weather/subscribe_forecast`, daily/hourly, is the command to confirm) and the extra HA calls F-AAG-03 needs: display precision, translated state strings and icons.

Verification is ci: the component has no visible output; its consumers (P3.6, P3.7, P3.11) carry the hardware checks.

## Result

**What changed**

- Socket decision, ADR 0017 item 1: the subscription shares the TLP socket. PLAN 5.1 is amended with one bullet.
  - `TlpClient` publishes `channel: StateFlow<HaChannel?>` for each registered connection and clears it when the connection ends.
  - `HaChannel.call` and `subscribe` take ids from the shared counter. The read loop routes `event` messages by subscription id.
  - Reconnect, backoff, keepalive and token refresh stay with the TLP client, unchanged.
- `EntityNeeds` (core, plain JVM) builds the subscription from settings and the shown mode:
  - At a Glance entities;
  - the weather, forecast and entity widgets while `widgets.shown` is on and the widget is enabled with an entity;
  - the weather scene's entity, plus `sun.sun` and its daily forecast.
  
  Calendar mode needs nothing, and empty needs open nothing.
- `EntityDataConnection` (`android/ha`):
  - `subscribe_entities` with the explicit list, never an empty one, and `weather/subscribe_forecast`. `CompressedStates` applies HA's `a`, `c` (`+`/`-`) and `r` events, and missing entities show as unavailable.
  - Display data comes after the live subscriptions: `list_for_display`, `get_translations` and `get_icons`. `DisplayData` gives `stateText`, `icon` and `precision`, falling back the way HA's frontend does.
  - Exposes `states`, `forecasts`, `display` and `subscribed` as StateFlows.
  - Keeps last-known data and resubscribes on each new connection.
  - Refusals and drops are logged and never fatal. Nothing is sent on a connection that has gone.
- Lifecycle: `ScreensaverManager` hands `EntityNeeds.of(settings, shownMode)` to the connection after every outcome. That opens it with the screensaver, re-targets it on a settings change and closes it on dismissal. `TabulaService` feeds the live TLP channel in.
- Mock device: `mockdevice/hacore.py` implements this slice of HA core in HA's real formats, on the test server's socket. It adds the `/test/entity`, `/test/forecast`, `/test/display` and `/test/drop` hooks, and the report lists live HA subscriptions and commands.
- Tests:
  - `EntityNeedsTest` (5);
  - `EntityStatesTest` (4);
  - `EntityDataConnectionTest` (5, scripted channel);
  - `EntityDataServerTest`: the real client over a real socket against the extended server. It covers the explicit list, `a`/`c`/`r` with `+`/`-`, unavailable entities, forecasts, display data, a dropped connection with resubscription, close on dismissal, a clean TLP report and no credential in the logs;
  - one `ScreensaverManagerTest` case;
  - `mockdevice/tests/test_hacore.py` (5).
  
  `TestServerProcess` moved to a shared `PythonTestServer.kt`.
- ADR 0017, decisions index, PROVENANCE rows.

**ADR notes:**
- ADR 0017 item 1: one socket, with the PLAN 5.1 amendment.
- Item 4: forecasts come from `weather/subscribe_forecast`.
- Item 5: the display-data calls.
- Item 6: none of the commands is `require_admin`, and `subscribe_entities` filters by `POLICY_READ`.

**Deviations and open questions**

- The black mode's hide-everything option (F-SSV-06) has no settings key, so black mode still opens the subscription when overlays are configured. The key and its gate in `EntityNeeds` belong to whichever packet adds the option (ADR 0017 consequences).
- Per-slot overlay overrides (F-SSV-18) are not applied. P3.12 hands `EntityNeeds` the effective settings.
- Clock night mode's "hide widgets and At a Glance at night" (F-SSV-10) keeps the subscription open. It is a drawing choice, and data keeps flowing for when the light rises.
- Display data is fetched once per subscription, not refreshed live.
