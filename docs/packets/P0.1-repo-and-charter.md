# P0.1 — Repo and charter

Side: build   Tier: light   Depends on: none
Verification: ci
Status: in-review

## Why

Every later packet assumes a repository with standing instructions, clean-room rules, a packet workflow and one way to build and check. This packet creates them.

## Read first

- `docs/PLAN.md` sections 1, 2, 6 and 7.1 (P0.1)

## Do

1. Create the monorepo with LICENSE (Apache-2.0), `.gitignore`, README (per the public framing rule), AGENTS.md (from plan sections 1–2, no doc cache paths), PROVENANCE.md (with the human-exception note), `docs/packets/TEMPLATE.md` and symlinked tool instruction files.
2. Record the repository and the package name `net.lockney.tabula` in an ADR.
3. Added at Thomas's request: make the repo workable from cloud VMs, with one standalone build mechanism, a clean layout, a colocated static-site website (placeholder), GitHub issues as the unit of delegation, and all development in git worktrees.
4. Import the plan into the repo as `docs/PLAN.md`.

## Out of scope

Component code (integration, mock device, Android, panel), schema, fixtures, FEATURES.md content.

## Done when

- `make setup && make check` passes on a fresh clone.
- AGENTS.md contains the build-side clean-room rules and the definition of done.
- A grep for the doc cache directory name returns nothing.

## Hand back

Result section below.

**Deviations**

- ADR numbers 0001 and 0002 are reserved by the plan for P0.3 and P0.4, so this packet's ADRs are 0003–0006.
- The doc cache grep was not run. By design the build side does not know the cache directory name. Thomas (or a spec-side context) should run `git grep -i <cache dir name>` on this branch before merge.
- Website builder is VitePress (Thomas's choice), which brings Node in at P0.1 instead of Phase 5.

**Open questions**

- Website hosting and domain (ADR 0005 defers it).
- Whether `main` gets branch protection requiring the `ci` check and a review.
