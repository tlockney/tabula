# P3.1 — Settings schema v2 and options flow

Side: build   Tier: deep   Depends on: none
Verification: ci
Issue: #59
Status: done

## Why

Every Phase 3 feature is driven by per-device settings: clock faces, night mode, the weather scene, the photo slideshow, website mode, At a Glance, corner widgets and the schedule. The v1 schema covers only Phases 1–2, so this packet bumps `schema_version` to 2 with the Phase 3 keys, the migration, the Kotlin codegen (which cannot yet express some constructs the new keys need) and the options flow that edits them. It gates every other packet in this phase.

Protocol assessment: Phase 3 needs **no TLP change here**. The `screenshot` command, its HTTP upload (PROTOCOL 4.5, 5) and the `schedule` trigger value already exist in v1; At a Glance and the weather scene use HA's own `subscribe_entities` API over the device credential, not TLP. P3.9 later adds one capability-gated command (`slide`), which is additive and does not bump the protocol major (PROTOCOL 8). The settings schema is versioned separately and does bump: 1 → 2.

## Do

1. Choose the Phase 3 schema bounds and defaults, and extend ADR 0002 with them (same pattern as its "Screen control (P2.3)" section). Every new property carries `x-tabula-role` and `x-tabula-feature` tags, as the schema header requires. The extension also pre-commits one interface: the night-mode flag (`NightState`, plain JVM in `android/core`, defaulting to never-night) that P3.4 implements and P3.6/P3.11 consume. This packet lands the `NightState` Kotlin interface and its never-night default in `android/core`, with a JVM test, so P3.6 and P3.11 compile against it — so the At a Glance and widget packets do not wait on P3.4's hardware-dependent work.
2. Add the Phase 3 keys to `schema/settings.schema.json`, bump `x-tabula-schema-version` to 2:
   - `screensaver.clock` (F-SSV-08, F-SSV-09): face (`digital` | `analog`), font family and weight (system fonts only; nothing bundled in this phase), 12/24-hour, seconds, AM/PM marker, date line, size, text color, background color, background source (empty | local file path | URL) with a re-fetch interval, and a darkening strength for the readability layer.
   - `screensaver.night_mode` (F-SSV-10): enabled, light threshold and hysteresis (lux), hide background image, hide overlays (widgets, At a Glance), power-off delay in night mode (minutes, 0 = never), and the black-screen alternative flag.
   - `screensaver.weather` (F-SSV-11): weather entity id, place name, clock overlay, info bar, lightning toggle.
   - `screensaver.photos` (F-SSV-12): source (`folder` | `picker` | `url` | `media_browser` — include `media_browser` in the enum now even though P3.9 builds it, so that packet does not bump the schema again), folder path, single image URL, slide interval, transition, fit, shuffle, include-subfolders, edge taps, EXIF details overlay.
   - `screensaver.website` (F-SSV-13, F-SSV-14): URL, zoom, double-tap-to-dismiss.
   - `screensaver.dim_brightness` (F-SSV-07): the dim mode's own backlight level, so dim stops borrowing `screensaver.brightness` (ADR 0013 item 4 called this out; P3.14 uses the key).
   - `screensaver.pixel_shift` (F-SSV-22): enabled, interval and amplitude — the image-retention shift P3.14 builds.
   - `screensaver.fade` (F-SSV-23): enabled — the in/out fade P3.14 builds.
   - `at_a_glance` (F-AAG-01, F-AAG-02): entity id list (bounded; the bound is a constant chosen in ADR 0002), style (`pill` | `plain`), hide names, monochrome icons, scale, font.
   - `widgets` (F-WGT-01): global shown switch, scale, font, vignette, and per-widget objects — small clock, weather, forecast, battery, entity — each with `enabled`, a corner (`tl` | `tr` | `bl` | `br`) and its own options (F-WGT-03 to F-WGT-06, F-WGT-09).
   - `schedule` (F-SSV-18): enabled switch and a bounded array of slots `{start (HH:MM), mode, brightness, power_off_delay, presence_dismiss, widgets, at_a_glance}` where `null`/absent means "inherit". The `power_off_delay` override is carried by the schema now; the countdown it overrides (F-SSV-19) is out of scope and the key no-ops until that feature ships.
3. Extend `tools/codegen.py` for whatever the new keys need (arrays of scalars and objects, nested optional objects), with tests. Keep the rule that codegen raises on unsupported constructs.
4. Regenerate the Kotlin settings classes; `make codegen-drift` must be clean. Add settings fixtures: a valid defaults document, a valid fully-populated Phase 3 document, and known-bad fixtures for the new bounds.
5. Integration — stored documents need **no** `STORAGE_VERSION` migration: `SettingsStore.async_load`/`async_save` already fill defaults through `_merge_defaults` on load, so a v1 store upgrades on its first load. Do not build a second mechanism. But `_merge_defaults` merges one level only, and v2 nests objects under `screensaver` and per-widget objects under `widgets` — make it recursive for nested objects, with arrays and `null` (the schedule's "inherit") replaced, not merged, so a partial nested document from the options flow merges into defaults instead of dropping them. Test both.
6. Integration — **down-translation v2 → v1 is required, not incidental.** An installed APK stays on schema 1 until it is updated, and the device's `SettingsCodec` rejects unknown keys. Add `DOWNS[2]` to the migrations module, pruning every key v1 does not know — including nested keys inside existing groups (`screensaver.clock`, `.night_mode`, `.weather`, `.photos`, `.website`), not only the new top-level groups. Keep a frozen copy of the v1 schema (e.g. `schema/settings.schema.v1.json`) for the test.
7. Extend the options flow's per-device form to the new keys; list-valued keys need a usable editor, not a polished one — the Tabularium (Phase 5) is the real settings UI. For the schedule's array of objects, name the editor explicitly (HA's object selector or a YAML-style field, validated against the schema on submit) so the executor does not burn the timebox on a custom UI. `revision` must not bump on load-time default filling (it does not today; keep it that way).
8. `PROVENANCE.md` rows for the new settings keys.

### What changed

- `schema/settings.schema.json` is version 2 with every Phase 3 key the packet lists: `screensaver.clock`, `.night_mode`, `.weather`, `.photos` (with `media_browser` in the source enum), `.website`, `dim_brightness`, `.pixel_shift`, `.fade`, `at_a_glance`, `widgets` (global keys + small_clock/weather/forecast/battery/entity objects) and `schedule` (bounded slots; `null`/absent = inherit). All bounds and defaults are chosen and reasoned in a new ADR 0002 section, "Settings schema v2 (P3.1)", which also pre-commits the NightState contract.
- `schema/settings.schema.v1.json` (and a bundled copy next to the integration) freezes v1 for the down-translation; `tools/validate_frames.py` now checks that bundle pair like the current schema's.
- `migrations.DOWNS[2]`: prunes every key the v1 schema does not know, recursing into the groups v1 defines, so the new nested keys inside `screensaver` go too. A schema-1 device (the mock device, and the golden register fixture's device in the options tests) now receives translated v1 documents end to end.
- `SettingsStore._merge_defaults` is recursive for nested objects; arrays and nulls replace, not merge. A stored v1 document loads as v2 with nested defaults filled, revision untouched (no new mechanism; `STORAGE_VERSION` unchanged).
- The options flow covers the new keys from the schema alone (97 flat fields, labels in `strings.json`/`en.json`). List leaves get a multi-line text editor: one item per line for scalar arrays (At a Glance entities, the entity widget's visible values), YAML for the schedule's slots — parsed and schema-validated on submit, with an error inside a slot mapped onto the `schedule_slots` field, and bad YAML reshowing on that field.
- `tools/codegen.py` learned nullable scalars (`["integer", "null"]` etc.), arrays of scalars (per-item pattern/length/range checks, maxItems) and of objects (a generated data class per item), and required object properties (emitted without a Kotlin default, so an absent `slot.start` fails decoding). Unsupported constructs still raise. `Settings.kt` regenerated at `SCHEMA_VERSION 2`.
- `NightState` in `android/core` (`net.lockney.tabula.core.screensaver`): plain-JVM interface with `isNight` and a never-night default, with a JVM test, as the ADR pre-commits. P3.4 implements it; P3.6/P3.11 compile against it.
- Fixtures: `schema/fixtures/settings/v2/` with defaults (generated from the schema), empty, a fully-populated Phase 3 document, and 37 known-bad documents with recorded failure pointers. The v1 fixtures stay and now also assert they still validate under v2 (the bump is additive).
- `PROVENANCE.md` rows for every new settings key and the down-translation/editor behavior.

### Deviations and decisions

- **Codegen naming.** v2 has `screensaver.weather` and `widgets.weather`; generated data classes and Regex vals are now named by their full path (the enums already were), so `ChimeByLevel` became `NotificationsChimeByLevel` — no consumer references it. A pattern shared by several fields (the color pattern) now declares one Regex val named after its first user, instead of raising.
- **The mock device stays on schema 1.** The packet does not ask to bump it; leaving `mockdevice` at schema_version 1 keeps a genuine "installed v1 APK" in the e2e suite, which now exercises `DOWNS[2]` on every `make test` (the options-flow e2e test observes the translated document on the wire).
- **Schedule editor.** Named explicitly as the packet suggested: a YAML-style multi-line field validated against the schema on submit (no custom UI; the Tabularium is Phase 5). Scalar arrays are one-item-per-line text fields for the same reason.
- **Required properties in codegen** reject carrying a schema default (required and defaulted contradict), and `minItems` on arrays raises as unsupported — neither is used by v2; both keep the generator honest.
- **Widget corner defaults can collide** (five widgets, four corners; `entity` defaults to `tr` like `weather`): harmless because all widgets default to disabled, and the resolution rule is the device's (F-WGT-01). Reasoning in ADR 0002.

### Review changes (PR #73)

Two review nits folded in:

1. The e2e tests now validate every set_settings the schema-1 mock device received strictly against the frozen v1 schema (`assert_no_v2_keys_reached_the_device`), so a leak of any v2-only key — nested ones included — fails the test. Mutation-verified: replacing `DOWNS[2]`'s prune with an identity function made all four push tests fail with "the schema-1 device received a v2-only key: Additional properties are not allowed ('at_a_glance', 'schedule', 'widgets' … 'clock', 'dim_brightness', 'fade', 'night_mode', 'photos', 'pixel_shift', 'weather', 'website' were unexpected)"; reverting the prune made them pass again.
2. `NightState` is observable, not polled: `addListener` registers a `Listener` for night-mode transitions and returns a removal function (android/core has no coroutine dependency, so a listener matches the module's style; a StateFlow would be the alternative). The never-night default keeps `isNight` false and never fires a listener. The JVM test covers transitions and removal; ADR 0002's NightState paragraph and the P3.4/P3.6/P3.11 wording are aligned to the observable contract.

### Second-review changes (PR #73)

One blocker, folded in: ADR 0002's v2 section was missing the `screensaver.photos` constants. A photos table (source/folder_path/image_url/slide_interval/transition/fit/shuffle/include_subfolders/edge_taps/exif_details, a reasoning line each) now sits between the night-mode and weather/website tables; the widget rows gained the missing `attribute`/`name` maxLength 64 bounds and `visible_values`' 0–64 chars per item; the clock color rows now carry the literal defaults (`#FFFFFFFF`/`#FF000000`). A full audit of every v2 leaf's default and bounds against the ADR section found no other gaps. A new schema test (`test_v2_defaults_and_bounds_are_documented_in_adr_0002`) parses ADR 0002's v2 tables and requires one row per v2 leaf carrying its default, every numeric bound and every enum member — mutation-verified: deleting the photos `shuffle` row makes it fail with `screensaver/photos/shuffle: no row in ADR 0002's settings-v2 section carries its default/bounds ['false']`. The review's two nits are also fixed: the dead `_enum_index` state is gone from tools/codegen.py (output unchanged, codegen-drift clean), and the no-op `if TYPE_CHECKING: pass` block is gone from options_flow.py.
