# P3.1 — Settings schema v2 and options flow

Side: build   Tier: deep   Depends on: none
Verification: ci
Issue: TBD
Status: ready

## Why

Every Phase 3 feature is driven by per-device settings: clock faces, night mode, the weather scene, the photo slideshow, website mode, At a Glance, corner widgets and the schedule. The v1 schema covers only Phases 1–2, so this packet bumps `schema_version` to 2 with the Phase 3 keys, the migration, the Kotlin codegen (which cannot yet express some constructs the new keys need) and the options flow that edits them. It gates every other packet in this phase.

Protocol assessment: Phase 3 needs **no TLP change here**. The `screenshot` command, its HTTP upload (PROTOCOL 4.5, 5) and the `schedule` trigger value already exist in v1; At a Glance and the weather scene use HA's own `subscribe_entities` API over the device credential, not TLP. P3.9 later adds one capability-gated command (`slide`), which is additive and does not bump the protocol major (PROTOCOL 8). The settings schema is versioned separately and does bump: 1 → 2.

## Do

1. Choose the Phase 3 schema bounds and defaults, and extend ADR 0002 with them (same pattern as its "Screen control (P2.3)" section). Every new property carries `x-tabula-role` and `x-tabula-feature` tags, as the schema header requires. The extension also pre-commits one interface: the night-mode flag (`NightState`, plain JVM in `android/core`, defaulting to never-night) that P3.4 implements and P3.6/P3.11 consume — so the At a Glance and widget packets do not wait on P3.4's hardware-dependent work.
2. Add the Phase 3 keys to `schema/settings.schema.json`, bump `x-tabula-schema-version` to 2:
   - `screensaver.clock` (F-SSV-08, F-SSV-09): face (`digital` | `analog`), font family and weight (system fonts only; nothing bundled in this phase), 12/24-hour, seconds, AM/PM marker, date line, size, text color, background color, background source (empty | local file path | URL) with a re-fetch interval, and a darkening strength for the readability layer.
   - `screensaver.night_mode` (F-SSV-10): enabled, light threshold and hysteresis (lux), hide background image, hide overlays (widgets, At a Glance), power-off delay in night mode (minutes, 0 = never), and the black-screen alternative flag.
   - `screensaver.weather` (F-SSV-11): weather entity id, place name, clock overlay, info bar, lightning toggle.
   - `screensaver.photos` (F-SSV-12): source (`folder` | `picker` | `url` | `media_browser` — include `media_browser` in the enum now even though P3.9 builds it, so that packet does not bump the schema again), folder path, single image URL, slide interval, transition, fit, shuffle, include-subfolders, edge taps, EXIF details overlay.
   - `screensaver.website` (F-SSV-13, F-SSV-14): URL, zoom, double-tap-to-dismiss.
   - `screensaver.dim_brightness` (F-SSV-07): the dim mode's own backlight level, so dim stops borrowing `screensaver.brightness` (ADR 0013 item 4 called this out; P3.14 uses the key).
   - `screensaver.pixel_shift` (F-SSV-22): enabled, interval and amplitude — the image-retention shift P3.14 builds.
   - `screensaver.fade` (F-SSV-23): enabled — the in/out fade P3.14 builds.
   - `at_a_glance` (F-AAG-01, F-AAG-02): entity id list (bounded; the bound is a constant chosen in ADR 0002), style (`pill` | `plain`), hide names, monochrome icons, scale, font.
   - `widgets` (F-WGT-01): global shown switch, scale, font, vignette, and per-widget objects — small clock, weather, forecast, battery, entity — each with `enabled`, a corner (`tl` | `tr` | `bl` | `br`) and its own options (F-WGT-03 to F-WGT-06, F-WGT-09).
   - `schedule` (F-SSV-18): enabled switch and a bounded array of slots `{start (HH:MM), mode, brightness, power_off_delay, presence_dismiss, widgets, at_a_glance}` where `null`/absent means "inherit". The `power_off_delay` override is carried by the schema now; the countdown it overrides (F-SSV-19) is out of scope and the key no-ops until that feature ships.
3. Extend `tools/codegen.py` for whatever the new keys need (arrays of scalars and objects, nested optional objects), with tests. Keep the rule that codegen raises on unsupported constructs.
4. Regenerate the Kotlin settings classes; `make codegen-drift` must be clean. Add settings fixtures: a valid defaults document, a valid fully-populated Phase 3 document, and known-bad fixtures for the new bounds.
5. Integration — stored documents need **no** `STORAGE_VERSION` migration: `SettingsStore.async_load`/`async_save` already fill defaults through `_merge_defaults` on load, so a v1 store upgrades on its first load. Do not build a second mechanism. But `_merge_defaults` merges one level only, and v2 nests objects under `screensaver` and per-widget objects under `widgets` — make it recursive for nested objects, with arrays and `null` (the schedule's "inherit") replaced, not merged, so a partial nested document from the options flow merges into defaults instead of dropping them. Test both.
6. Integration — **down-translation v2 → v1 is required, not incidental.** An installed APK stays on schema 1 until it is updated, and the device's `SettingsCodec` rejects unknown keys. Add `DOWNS[2]` to the migrations module, pruning every key v1 does not know — including nested keys inside existing groups (`screensaver.clock`, `.night_mode`, `.weather`, `.photos`, `.website`), not only the new top-level groups. Keep a frozen copy of the v1 schema (e.g. `schema/settings.schema.v1.json`) for the test.
7. Extend the options flow's per-device form to the new keys; list-valued keys need a usable editor, not a polished one — the Tabularium (Phase 5) is the real settings UI. For the schedule's array of objects, name the editor explicitly (HA's object selector or a YAML-style field, validated against the schema on submit) so the executor does not burn the timebox on a custom UI. `revision` must not bump on load-time default filling (it does not today; keep it that way).
8. `PROVENANCE.md` rows for the new settings keys.

## Out of scope

- Any device behavior (the Android packets below).
- Settings entities (P3.2).
- Any TLP change (P3.9's `slide` command is the only Phase 3 addition, and it is P3.9's).
- Weather scene, gallery, website rendering, schedule engine.
