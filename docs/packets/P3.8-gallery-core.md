# P3.8 — Gallery core (photo slideshow)

Side: build   Tier: deep   Depends on: P3.1
Verification: hardware
Issue: #66
Status: ready

## Why

F-SSV-12's photo slideshow, minus the HA media-browser source: a folder on the device, photos picked with the system picker (copied into app storage), and a single image URL fetched fresh per slide. Transitions, fit modes, panel-resolution decode with prompt release, edge-tap zones and the EXIF details overlay. Deep because the image pipeline is the most memory-sensitive code in the app and the target is a low-RAM tablet.

Unverified device fact: nothing has measured decode memory or GC pressure on the HD 10 Plus (the Phase 2 hardware checks #15–#20 have not run). The hardware script therefore includes `dumpsys meminfo` assertions alongside the visual checks; no separate spike is needed, but the JVM tests must cover the release/reuse logic.

## Do

1. Playlist built when the screensaver starts (new files appear next time); shuffle and include-subfolders for the folder source; the picker source copies into app storage (no broad storage permission — SAF, and the copy survives reboots). The `media_browser` source is in the schema from P3.1 but served by P3.9; until that packet lands, `source: media_browser` behaves as an unbuilt source and the ADR 0013 item-3 clock stand-in shows.
2. Transitions (none, crossfade, slide, zoom, slow pan-and-zoom for stills, random per slide) and fit (letterbox, smart fill with a blurred darkened enlargement of the photo filling the bars when shapes differ a lot, always fill).
3. Decode at panel resolution; the previous slide's bitmap is released before the next is shown (an explicit decodable invariant in the JVM tests with fake bitmaps).
4. The URL source: the current photo stays until the next has loaded; a failed fetch keeps it and retries later; a small history of recent photos allows stepping back.
5. Edge zones: a tap near one side edge goes back one slide, near the other goes forward, and the interval restarts; elsewhere a tap dismisses (F-SSV-04's exception).
6. EXIF details overlay (date taken, camera details; no location lookup), placed in a free corner, displaced by corner widgets when those land (F-WGT-02).
7. JVM tests: playlist build (shuffle determinism injectable), transition/fit selection, decode/release lifecycle, URL loader (fake transport: failure keeps current, history, fresh-fetch-per-slide), edge-tap zoning.
8. `tools/device/check_p38.sh` (visual checks plus `dumpsys meminfo` before/after N slides) and a DEVICE.md section, including how the test photos get onto the device (ADB push into app storage or the picker).
9. `PROVENANCE.md` rows.
