# P10.0 — Spec: camera-based presence

Side: spec   Tier: standard   Depends on: none
Verification: review
Issue: #87
Status: ready

This is a spec-side packet. A context that executes it must not write code in this repository afterwards.

## Why

Plan section 4 now brings the tablet's own camera into scope as a presence sensor (Phase 10). `docs/FEATURES.md` lists camera motion and face wake only as deferred or dropped hooks, so the build side has no behavior to build from. This packet adds that behavior to `docs/FEATURES.md`.

Thomas's request (2026-11-21), the design input from the project owner: "Go ahead and add camera-based detection to the plan."

## Do

1. Add entries for camera-based presence, with new stable IDs (next free numbers in the area that fits, or a new area if the entries do not fit an existing one; update the area table). Cover at least:
   - what the camera detects (motion, a face, or both) and what each does: dismiss the screensaver, hold the idle timer, wake the panel from off;
   - how camera presence combines with the HA presence source of F-SSV-24 (one presence rule fed by several sources, or separate rules);
   - what HA sees (entities, events) and what is never sent;
   - privacy: when the camera may run, what the user is shown while it runs, consent (F-DSH-09's genuine-tap rule), and what happens when the permission is missing;
   - interaction with the schedule (F-SSV-18), lockdown, another app in front, and panel-off;
   - settings the user has (sensitivity and similar), without values.

4. Open questions for the architect go in "Open:" lines, not in design.
