# P2.1 — Service, pairing, HA client

Side: build   Tier: deep   Depends on: P1.2, P2.0
Verification: hardware
Issue: #15
Status: ready

## Why

The app's backbone: a foreground service that pairs with HA, stores its credential securely and keeps the TLP connection up. Starts the device runbook.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 5.1–5.4, 5.9 and 7.3 (P2.1)
- `docs/PROTOCOL.md`
- `docs/decisions/0001-ha-platform.md`, `docs/decisions/0002-constants.md`
- The Echo Show feasibility ADR written by P0.6 (`docs/decisions/README.md` lists it), for the Echo Show boot check
- `docs/DEVELOPMENT.md`
- `android/`

## Do

1. Foreground service, boot receiver, pairing screen (code and device_id), nonce and claim, Keystore-backed credential storage, persisted device_id.
2. WebSocket client: auth, register with versions, command loop, ACKs, backoff, heartbeat.
3. Battery, charging, connectivity and app-version sensors.
4. Start `docs/DEVICE.md`: ADB provisioning (install, `pm grant`, `appops set` for WRITE_SETTINGS, deviceidle whitelist, `dpm set-active-admin`) as a script in `tools/device/`, plus ADB recovery steps.
5. Write the hardware check as a script in `tools/device/`.

## Out of scope

- Dashboard WebView (P2.2), screen control (P2.3).

## Done when

- CI: `make check` passes, with unit tests for the client state machine.
- Hardware (pasted by the hardware verifier): the tablet pairs and appears in HA; airplane mode makes it unavailable; reconnect brings it back. ADB-scripted check plus HA state query.
- Hardware, only if P0.6 said go (pasted by the hardware verifier): provision the same build on one Echo Show per DEVICE.md, launch it and pair it (a freshly installed app is in the stopped state and gets no boot broadcast until launched once), then reboot and record whether the service starts on boot (`adb logcat -d` lines from the boot receiver and `adb shell dumpsys activity services net.lockney.tabula`). If P0.6 has not concluded, skip this observation and say so in the Result section. This is an observation, not a pass/fail gate for P2.1; a blocked boot start goes to the architect (plan section 9).
