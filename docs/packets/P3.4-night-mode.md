# P3.4 — Clock night mode

Side: build   Tier: standard   Depends on: P3.3
Verification: hardware
Issue: #62
Status: ready

## Why

F-SSV-10: below a light threshold from the tablet's own sensor (never an HA illuminance entity), the clock switches to a night color scheme — text and widgets in one dim accent color on a dark background — with hysteresis to switch back, optional hiding of the background image and of the overlay row, and an optional panel power-off after night mode has lasted a set time (device admin; a black-screen alternative when permission is missing or the sensor stops reporting).

Unverified device fact this packet depends on: whether the Fire HD 10 Plus light sensor keeps reporting once the panel is powered off (F-SSV-10 and F-SCR-14 both warn it may not), and the P2.3 screen-control hardware checks (#17) have not run. The packet therefore starts with a timeboxed device spike that settles it, recorded in an ADR; the night power-off design follows whatever it finds.

## Do

1. **Timeboxed device spike (first, timebox: 1 working day)**: on the Office Kiosk, with the device admin active, power the panel off via the P2.3 path and log light-sensor readings for a bounded period (constant chosen from ADR 0002's night-mode section), then power it on. Record in an ADR whether readings continue at panel-off, and whether rising light is observable. The night power-off path is designed from this: if the sensor stops, the black-screen alternative is the documented default for this hardware and the ADR says so.
2. Night state machine (plain JVM, testable): threshold entry, hysteresis exit, the settings options, and the night color scheme applied to the clock face (P3.3's views expose their colors). This packet implements the `NightState` interface pre-committed by P3.1's ADR 0002 extension (`android/core`, never-night default until this packet lands): it is observable — `addListener` reports every transition, with the state machine owning the threading — and P3.6 and P3.11 already consume it that way.
3. Night power-off countdown: only while the clock mode is showing; notifications and other foreground content (P2.5's cards today) keep the panel on and restart the countdown; rising light turns the panel back on. Missing device-admin permission: skipped without prompting, warning logged. Black-screen alternative: plain black at minimum brightness, nothing drawn, touch returns to the dashboard.
4. The countdown restarts when the screensaver restarts or the mode changes away from clock.
5. JVM tests for the state machine (threshold, hysteresis, options, countdown restarts, foreground-app hold) with an injected clock and sensor.
6. `tools/device/check_p34.sh` and a DEVICE.md section; it can share a device session with #17/#18's pending hardware checks.
7. `PROVENANCE.md` rows.
