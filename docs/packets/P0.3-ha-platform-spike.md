# P0.3 — HA platform spike

Side: build   Tier: deep   Depends on: P0.1   Timebox: 3 working days
Verification: hardware
Issue: #6
Status: ready

## Why

The architecture (plan section 5) rests on assumptions about Home Assistant and the Fire WebView. This spike confirms or corrects them with throwaway code against a dev HA instance before the protocol is written.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 3 and 5, and 7.1 (P0.3)
- HA core and frontend source, and the HA Companion Android app source (Apache-2.0 prior art; record what you learned in the ADR)

## Do

1. Hub entry plus a `SOURCE_INTEGRATION_DISCOVERY` flow triggered from a custom HTTP view.
2. Which credential type an integration-created, non-admin user can use for (a) custom WebSocket commands and (b) loading the dashboard via external auth.
3. Frontend external auth in an Android WebView (how the Companion app does it).
4. Custom `websocket_api` subscription delivery, practical message-size limits, and resolving the caller's user inside a command (for connection binding).
5. NotifyEntity and media_player `play_media` receiving a `tts.speak` URL, and whether that URL is fetchable with the device credential.
6. Hardware: the Office Kiosk's WebView version against the HA frontend's supported-browser floor, and how WebView updates arrive on Fire OS. Note what this means for PF1007L frames. The hardware verifier runs the ADB command the executor writes down.
7. `assist_satellite` base class requirements (notes only, for Phase 7).
8. The minimum HA version that supports all of the above.
9. Write `docs/decisions/0001-ha-platform.md`: what worked (with evidence), what didn't, the chosen fallbacks.

## Out of scope

- Production code. Spike code is throwaway and is not merged.
- Protocol design (P0.4).

## Done when

- `docs/decisions/0001-ha-platform.md` answers items 1–8, each with pasted evidence.
- Item 6 has device output pasted by the hardware verifier.
- `make check` passes.

Result section: summary per item. If items 1–3 or 6 fail, say so first: the architect revises plan sections 5.2, 5.3 or 5.8 before Phase 1. If the timebox runs out, hand back findings so far.
