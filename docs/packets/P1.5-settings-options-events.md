### Deviations / decisions

- Settings are data in a single HA Store keyed by Tabula device id, not entries in the HA device registry and not the config entry's options; the options flow leaves entry options untouched (`async_create_entry` with `data=None`). Rationale: plan 5.6 places per-device settings in HA; one flat doc per device matches the TLP set_settings payload. The entry-options route was rejected because settings are per device, and one hub entry can hold many tablets.
- The revision stored by HA starts at 1 on first save and increments only when data changes (PROTOCOL.md 4.2/4.5). register_result returns HA's stored revision; a device that registers behind or ahead gets HA's document pushed over its subscription. The set_settings ACK's applied revision is recorded as the session's reported revision (PROTOCOL.md 4.6) so the next drift check compares against what the device confirmed.
- The options-flow form is generated by walking the bundled schema's x-tabula-role and x-tabula-feature tags (editable roles only; hardware leaves are excluded per F-MGT-03). Voluptuous carries only what the frontend enforces while typing (vol.In for enums, vol.Coerce(int) with vol.Range for bounds, strings accept blank; blank means unset for no-default leaves); the assembled document is re-validated against the JSON schema on submit. In this HA version vol-level failures raise InvalidData from the flow manager rather than re-showing the form; the test pins that contract. DeviceSelector takes a single config dict here: `selector.DeviceSelector({"filter": {"integration": DOMAIN}})`.
- Enum-only schema leaves carry no "type"; the walker defaults them to "string" (every v1 enum is strings).
- migrations/ is a translate-down registry (DOWNS keyed by version), empty at SCHEMA_VERSION 1; no translate-up exists because HA only ever holds documents at or below its own version and the store rejects higher ones at load.
- commands.py is a minimal shared send/await path (ulid command ids, COMMAND_TIMEOUT from ADR 0002) so P1.4 can grow it; only set_settings is implemented here.
- Event relay maps each accepted TLP event name to one tabula_* HA bus event; the enum in schema/tlp-v1.schema.json matches the relay table exactly (verified by test). media_finished -> tabula_media and page_changed -> tabula_page have no FEATURES.md item; they are independent design from PROTOCOL.md 4.7.
- HA prior art used as patterns (Apache-2.0, no code copied): helpers/storage.py Store lifecycle; websocket_api subscription idiom; options flow shape from core config flows; selector.DeviceSelector filter idiom.
- No changes to mockdevice were needed: it already registers over a paired credential, subscribes and answers set_settings, so the e2e tests drive it as-is.
