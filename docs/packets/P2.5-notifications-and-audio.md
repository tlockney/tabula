### Deviations / decisions

The brief, FEATURES, PROTOCOL and the ADRs left these open; the simplest
consistent choice is recorded here.

1. **The media fetch carries no credential; redirects are followed, bounded.**
   The task phrasing said "fetching them with the device credential per ADR
   0001", but ADR 0001 item 5 and PROTOCOL 4.5 say the opposite: the TTS
   proxy URL is unauthenticated, other HA media is signed, and the device
   *never* attaches its HA token to the fetch. Followed the ADR/PROTOCOL
   (`MediaFetcher` sends no Authorization header). Unlike the
   credential-bearing requests, this fetch *follows* redirects — it carries
   no secret for the P2.1 no-redirect rule to protect, and common CDN and
   podcast URLs answer with a 30x — but a https-to-http downgrade is refused
   and chains stop at `MEDIA_MAX_REDIRECTS` (ADR 0002). Review round: the
   download is also cancellable (an OkHttp call cancelled through
   `suspendCancellableCoroutine`) and capped at `MEDIA_MAX_BYTES`, so a
   replaced load stops fetching at once and an endless stream fails as
   `media_finished` reason `error` instead of filling storage.
2. **Cards over the screensaver (F-NTF-12): neither wake nor dismiss it.**
   A card draws above the screensaver overlay; a tap on a card removes only
   that card and is not user activity for the idle timer (F-NTF-08: "a tap
   does nothing else"), so the screensaver stays. "Brighten for
   notifications" (F-NTF-12 item 2) has no settings field and no ADR 0002
   default; deferred.
3. **The `command` dismiss reason is unreachable in v1.** TLP v1 has no
   dismiss command (PROTOCOL 4.5), so F-NTF-08's dismiss-by-ID (and its card
   ID in a result) cannot ride the protocol; tags replace, cards time out,
   and touch dismisses. Deferred with the protocol's next minor.
4. **Overflow eviction reports `replaced`.** F-EVT-02 names eviction as a
   dismissal cause, but the wire reason enum (PROTOCOL 4.7) has no such
   value; `replaced` (removed for another card) is the closest.
5. **Icons and text.** The `icon` argument is validated and kept on the card
   model, but v1 renders the severity's stock glyph and accent color
   (F-NTF-02): no Material Design icon set is bundled yet (sentence 2 of
   F-NTF-02 deferred). Limited Markdown (F-NTF-03) is not rendered; the
   message shows as plain text.
6. **Chime.** A synthesized tone (ToneGenerator) on the OS notification
   stream. The per-device notification volume channel (F-NTF-09/10) has no
   schema field and no ADR 0002 default, so the OS stream level is the
   volume; the sound library and file choice are deferred with it.
7. **Announcements are audio-only in v1** (F-TTS-04): a play_media with
   `announce: true` plays sound only — no card, no screen wake, no lead-in
   chime (F-TTS-05's chime/repeat have no settings). `play_media` ACKs when
   accepted; a fetch or decode failure arrives afterwards as
   `media_finished` with reason `error` (F-TTS-10 terminal state).
8. **Loading reports idle.** The `media_state` enum has no loading value
   (PROTOCOL 4.4), so the player reports playing only once prepared, and
   `set_volume`/`mute` apply at any time. `stop` with nothing playing is a
   no-op (F-TTS-06).
9. **New ADR 0002 rows:** `NOTIFICATION_EVENT_BUFFER` and
   `MEDIA_EVENT_BUFFER`, 16 events each (same reasoning as
   `SCREENSAVER_EVENT_BUFFER`: bounded while HA is down, drained at session
   start).
10. **Known follow-up for the architect:** the HA `media_player` volume
    slider changes the device's channel but is not written back to HA's
    settings store (unlike the screen light, ADR 0011 decision 1), so an
    unrelated settings push restores `audio.media_volume`. Hardware volume
    keys (F-MED-06) and ducking (F-TTS-08) are deferred.

### Review round (PR #52, "changes requested")

Both must-fixes and the should-fix are addressed on the media path; the
card hit-test nit is fixed too.

- **Must-fix 1 (media files never deleted, same-millisecond collisions).**
  Downloads now go to `File.createTempFile("tabula-media", null, cacheDir)`
  (unique names, so two plays in one millisecond never share a file). The
  manager owns the file: it is deleted when the playback ends, is replaced
  (including a load still fetching or decoding when the newer one arrives),
  fails to decode, or on error, and `MediaManager.sweepStale` clears any
  `tabula-media` leftover at service start (at most one per abrupt death;
  every playback reaches a terminal state, F-TTS-10). Tested in
  MediaManagerTest: file-deleted-on-end, on-error, on-replace, and the
  sweep.
- **Must-fix 2 (unbounded download, cancellation ignored).** The copy is now
  a chunked loop that checks the coroutine between chunks, and the OkHttp
  call is cancelled through a `suspendCancellableCoroutine` whose
  cancellation handler calls `call.cancel()` — which also unblocks the
  blocking read — so a replaced or stopped load stops fetching at once. A
  new ADR 0002 constant `MEDIA_MAX_BYTES` (50 MiB) caps the file: an
  endless stream (a radio URL) fails with HTTP 413 and the playback ends as
  `media_finished` reason `error`. Downloading was kept over streaming
  through MediaPlayer so the redirect rule and the cap stay under Tabula's
  control and are JVM-testable (a streamed path would hand redirects to
  MediaPlayer's own stack).
  Tested in the new MediaFetcherTest, against a real local HTTP server:
  cancellation of a stalled download returns promptly and leaves no file,
  and the cap fails with 413 and leaves no file.
- **Should-fix (redirects on external media).** Followed now, since this
  fetch carries no credential for the P2.1 rule to protect: a https-to-http
  downgrade is refused, chains stop at the new ADR 0002 constant
  `MEDIA_MAX_REDIRECTS` (5), and the no-Authorization-header rule is kept
  (tested: the served request has no Authorization header). The hop rule
  is unit-tested through `MediaFetcher.nextHop`.
- **Nit.** `NotificationCardsView.cardAt` converts the event's window
  coordinates through `getLocationInWindow` before the hit test, so a status
  bar or a non-immersive inset no longer offsets it.
