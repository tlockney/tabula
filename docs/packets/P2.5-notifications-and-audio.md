### Deviations / decisions

The brief, FEATURES, PROTOCOL and the ADRs left these open; the simplest
consistent choice is recorded here.

1. **The media fetch carries no credential, and redirects are refused.**
   The task phrasing said "fetching them with the device credential per ADR
   0001", but ADR 0001 item 5 and PROTOCOL 4.5 say the opposite: the TTS
   proxy URL is unauthenticated, other HA media is signed, and the device
   *never* attaches its HA token to the fetch. Followed the ADR/PROTOCOL
   (`MediaFetcher` sends no Authorization header, and a 3xx is an error, the
   P2.1 rule in Http.kt).
2. **Cards over the screensaver (F-NTF-12): neither wake nor dismiss it.**
   A card draws above the screensaver overlay; a tap on a card removes only
   that card and is not user activity for the idle timer (F-NTF-08: "a tap
   does nothing else"), so the screensaver stays. "Brighten for
   notifications" (F-NTF-12 item 2) has no settings field and no ADR 0002
   default; deferred.
3. **The `command` dismiss reason is unreachable in v1.** TLP v1 has no
   dismiss command (PROTOCOL 4.5), so F-NTF-08's dismiss-by-ID (and its card
   ID in a result) cannot ride the protocol; tags replace, cards time out,
   and touch dismisses. Deferred with the protocol's next minor.
4. **Overflow eviction reports `replaced`.** F-EVT-02 names eviction as a
   dismissal cause, but the wire reason enum (PROTOCOL 4.7) has no such
   value; `replaced` (removed for another card) is the closest.
5. **Icons and text.** The `icon` argument is validated and kept on the card
   model, but v1 renders the severity's stock glyph and accent color
   (F-NTF-02): no Material Design icon set is bundled yet (sentence 2 of
   F-NTF-02 deferred). Limited Markdown (F-NTF-03) is not rendered; the
   message shows as plain text.
6. **Chime.** A synthesized tone (ToneGenerator) on the OS notification
   stream. The per-device notification volume channel (F-NTF-09/10) has no
   schema field and no ADR 0002 default, so the OS stream level is the
   volume; the sound library and file choice are deferred with it.
7. **Announcements are audio-only in v1** (F-TTS-04): a play_media with
   `announce: true` plays sound only — no card, no screen wake, no lead-in
   chime (F-TTS-05's chime/repeat have no settings). `play_media` ACKs when
   accepted; a fetch or decode failure arrives afterwards as
   `media_finished` with reason `error` (F-TTS-10 terminal state).
8. **Loading reports idle.** The `media_state` enum has no loading value
   (PROTOCOL 4.4), so the player reports playing only once prepared, and
   `set_volume`/`mute` apply at any time. `stop` with nothing playing is a
   no-op (F-TTS-06).
9. **New ADR 0002 rows:** `NOTIFICATION_EVENT_BUFFER` and
   `MEDIA_EVENT_BUFFER`, 16 events each (same reasoning as
   `SCREENSAVER_EVENT_BUFFER`: bounded while HA is down, drained at session
   start).
10. **Known follow-up for the architect:** the HA `media_player` volume
    slider changes the device's channel but is not written back to HA's
    settings store (unlike the screen light, ADR 0011 decision 1), so an
    unrelated settings push restores `audio.media_volume`. Hardware volume
    keys (F-MED-06) and ducking (F-TTS-08) are deferred.
