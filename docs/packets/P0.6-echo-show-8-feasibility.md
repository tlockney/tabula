# P0.6 — Echo Show 8 feasibility

Side: build   Tier: standard   Depends on: none   Timebox: 1 working day (research part)
Verification: hardware
Issue: #32
Status: ready

## Why

The Echo Show 8 (2nd gen) is a v1 target (plan sections 3 and 4), but whether it can run Tabula at all is unverified. It runs a Fire OS build without an app store for third-party apps, and its home screen belongs to Alexa. This packet decides go or no-go before any Echo Show work is broken down, so no packet is built on an assumption.

## Read first

- `AGENTS.md`
- `docs/PLAN.md` sections 3, 4 and 7.1 (P0.6)
- `docs/decisions/0001-ha-platform.md` item 6 (read-only device check and the Chromium 67 frontend floor)

## Do

1. Research, from public sources, whether ADB can be enabled on the Echo Show 8 (2nd gen) through its own settings on current firmware. Clean-room rule: do not use the original product's documentation or code (AGENTS.md), even if a search turns it up. Record every source used.
2. Allowed means only: the device's own settings menus and standard `adb`. No exploits, rooting, bootloader unlocking or firmware downgrades. If ADB needs any of those, stop: the result is no-go.
3. Hardware (hardware verifier, read-only): if ADB is available, run the ADR 0001 item 6 command list, plus:

   ```sh
   adb shell getprop ro.product.device
   adb shell wm size
   adb shell wm density
   adb shell dumpsys sensorservice | grep -iE 'light|proximity'
   adb shell pm list features
   adb shell cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN
   ```

4. Hardware (hardware verifier, writes to the device; run only after step 3 and only if ADB is available): install a small open-source APK from F-Droid with `adb install`, start it with `adb shell monkey -p <package> 1`, and record whether it stays in the foreground over the home screen for 5 minutes and after pressing the screen's home control. Uninstall it afterwards.
5. Write a new ADR (next free number) with the findings, sources, pasted output and a go/no-go against these criteria:
   - ADB can be enabled by the allowed means.
   - A sideloaded app installs, launches and stays in the foreground.
   - The WebView is Chromium 67 or later (the frontend's legacy-build floor in ADR 0001).
6. Update `docs/PLAN.md` sections 3 and 4 with the result. On no-go, move the Echo Show to "Deferred" in section 4 and close #33 as not planned.

## Out of scope

- Any code for the Echo Show (that is P2.7).
- Voice, camera and microphone use.
- Other Echo Show models.

## Done when

- CI: `make check` passes.
- Hardware (pasted by the hardware verifier): the step 3 and step 4 output, or a statement that ADB could not be enabled by the allowed means and what blocked it.
- The new ADR states go or no-go against the three criteria, and plan sections 3 and 4 match it.

## Hand back

Result section: sources, pasted device output, the go/no-go and the ADR number. Set `awaiting-hardware` once the research and ADR draft are done and only device output is missing.
