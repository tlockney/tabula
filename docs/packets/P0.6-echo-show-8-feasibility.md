# P0.6 — Echo Show 8 feasibility

Side: build   Tier: standard   Depends on: none   Timebox: 1 working day (research part)
Verification: hardware
Issue: #32
Status: ready

## Why

The Echo Show 8 (2nd gen) is a v1 target (plan sections 3 and 4), but whether it can run Tabula at all is unverified. It is expected to run a Fire OS build with no app store for third-party apps and a home screen owned by Alexa. This packet decides go or no-go before any Echo Show work is broken down, so no packet is built on an assumption.

## Do

1. Research, from public sources, whether ADB can be enabled on the Echo Show 8 (2nd gen) through its own settings on current firmware. Record every source used.
   - Clean-room rule (AGENTS.md): do not open or read the original product's documentation, code or support pages. Skip any search result from that product's site or docs, even when it looks relevant. That product is likely to document Echo Show setup, so check each result's site before opening it.
2. Allowed means only: the device's own settings menus and standard `adb`. No exploits, rooting, bootloader unlocking or firmware downgrades. If ADB needs any of those, stop: the result is no-go.
3. Hardware (hardware verifier, read-only): if ADB is available, run the ADR 0001 item 6 command list, plus:

   ```sh
   adb shell getprop ro.product.device
   adb shell wm size
   adb shell wm density
   adb shell dumpsys sensorservice | grep -iE 'light|proximity'
   adb shell pm list features
   adb shell cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN
   ```

4. Hardware (hardware verifier; this writes to the device, so run it only after step 3): sideload test with the F-Droid client (package `org.fdroid.fdroid`), downloaded from f-droid.org.

   ```sh
   adb install F-Droid.apk
   adb shell monkey -p org.fdroid.fdroid 1
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'   # right after launch
   # leave the device untouched for 5 minutes (a test duration, not a product constant)
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'   # after 5 minutes
   # press the on-screen home control, then:
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'
   adb shell monkey -p org.fdroid.fdroid 1
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'   # after relaunch
   adb uninstall org.fdroid.fdroid
   ```

   Before the idle window, set the screen to stay on through the device's own display settings, so a sleeping screen is not mistaken for the device taking the app away. If the screen sleeps anyway, note it and repeat the window.

   Leaving the app on a home press is normal Android behavior; keeping it in front is kiosk lockdown (Phase 4). What matters here is that the device does not take the app out of the foreground by itself, and that the app can be brought back.
5. Write a new ADR (next free number; add its row to `docs/decisions/README.md`) with the findings, sources, pasted output and a go/no-go against these criteria:
   1. ADB can be enabled by the allowed means.
   2. The sideloaded app installs and launches, is still the resumed activity after 5 idle minutes, and is the resumed activity again after relaunch.
   3. The WebView is Chromium 67 or later (the frontend's legacy-build floor in ADR 0001).
   Start on boot is not tested here; P2.1 checks it on one Echo Show if this packet says go.
6. Update `docs/PLAN.md` to match the result. On go: confirm or correct the resolution and constraints in section 3. On no-go: move the Echo Show to Deferred everywhere it appears (sections 3, 4, 7.0, 7.3 and 9), and close #33 as not planned.

## Out of scope

- Voice, camera and microphone use.
- Other Echo Show models.
