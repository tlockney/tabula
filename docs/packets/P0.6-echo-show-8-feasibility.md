# P0.6 — Echo Show 8 feasibility

Side: build   Tier: standard   Depends on: none   Timebox: 1 working day (research part)
Verification: hardware
Issue: #32
Status: closed (decision: ADR 0026, owner go on the owner-unlocked LineageOS 18.1 path)

## Why

The Echo Show 8 (2nd gen) is a v1 target (plan sections 3 and 4), but whether it can run Tabula at all is unverified. It is expected to run a Fire OS build with no app store for third-party apps and a home screen owned by Alexa. This packet decides go or no-go before any Echo Show work is broken down, so no packet is built on an assumption.

## Do

1. Research, from public sources, whether ADB can be enabled on the Echo Show 8 (2nd gen) through its own settings on current firmware. Record every source used.
   - Clean-room rule (AGENTS.md): do not open or read the original product's documentation, code or support pages. Skip any search result from that product's site or docs, even when it looks relevant. That product is likely to document Echo Show setup, so check each result's site before opening it.
2. Allowed means only: the device's own settings menus and standard `adb`. No exploits, rooting, bootloader unlocking or firmware downgrades. If ADB needs any of those, stop: the result is no-go.
3. Hardware (hardware verifier, read-only): if ADB is available, run the ADR 0001 item 6 command list, plus:

   ```sh
   adb shell getprop ro.product.device
   adb shell wm size
   adb shell wm density
   adb shell dumpsys sensorservice | grep -iE 'light|proximity'
   adb shell pm list features
   adb shell cmd package resolve-activity -c android.intent.category.HOME -a android.intent.action.MAIN
   ```

4. Hardware (hardware verifier; this writes to the device, so run it only after step 3): sideload test with the F-Droid client (package `org.fdroid.fdroid`), downloaded from f-droid.org. Record the APK's version and its `shasum -a 256` in the ADR so the test can be repeated.

   ```sh
   adb install F-Droid.apk
   adb shell monkey -p org.fdroid.fdroid 1
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'   # right after launch
   # leave the device untouched for 5 minutes (a test duration, not a product constant)
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'   # after 5 minutes
   # press the on-screen home control, then:
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'
   adb shell monkey -p org.fdroid.fdroid 1
   adb shell dumpsys activity activities | grep -E 'mResumedActivity|topResumedActivity'   # after relaunch
   adb uninstall org.fdroid.fdroid
   ```

   Before the idle window, set the screen to stay on through the device's own display settings, so a sleeping screen is not mistaken for the device taking the app away. If the screen sleeps anyway, note it and repeat the window.

   Leaving the app on a home press is normal Android behavior; keeping it in front is kiosk lockdown (Phase 4). What matters here is that the device does not take the app out of the foreground by itself, and that the app can be brought back.
5. Write a new ADR (next free number; add its row to `docs/decisions/README.md`). It states that it supersedes the Echo Show sentence in ADR 0001's "Additional targets" paragraph (plan section 4 no longer drops the Echo Show 8), and the README row says so. Include the findings, sources, pasted output and a go/no-go against these criteria:
   1. ADB can be enabled by the allowed means.
   2. The sideloaded app installs and launches, is still the resumed activity after 5 idle minutes, and is the resumed activity again after relaunch.
   3. The WebView is Chromium 67 or later (the frontend's legacy-build floor in ADR 0001).
   Start on boot is not tested here; P2.1 checks it on one Echo Show if this packet says go.
6. Update `docs/PLAN.md` to match the result. On go: confirm or correct the resolution and constraints in section 3. On no-go: move the Echo Show to Deferred everywhere it appears (sections 3, 4, 7.0, 7.3 and 9), and close #33 as not planned.

## Result

Research part done; ADR [0007](../decisions/0007-echo-show-8-feasibility.md) drafted as **provisional no-go**, pending the device check.

Sources and findings: ADR 0007, "Research findings". In short, no readable public source shows ADB enabled on the Echo Show 8 2nd gen through its own settings. Every known working path to sideloading on any Echo Show is an exploit plus bootloader unlock (not allowed), including the October 2026 `athena` exploit for this model. Some XDA threads and one article could not be fetched from the research environment; the ADR records which, and the `athena` thread was checked in review.

`docs/PLAN.md` is unchanged until the device check concludes. Either outcome's plan edits are listed in ADR 0007, "Consequences".

Device output (hardware verifier): the owner's read-only USB probe, pasted on #32 — stock firmware exposes a single MTP interface (1949:01c1, Lab126 "Alexa"), no ADB interface. That settles criterion 1 against the settings-only path: no ADB on stock, so steps 3 and 4 of this packet never ran on stock firmware.

**Decision (owner, 2026-11-22, recorded in [ADR 0026](../decisions/0026-echo-show-8-owner-unlocked-target.md)).** The Echo Show 8 (2nd gen) stays a v1 target, as an unlocked device running the community LineageOS 18.1 (Android 11) image. The owner performs the bootloader unlock and the flash himself, by hand, from the public community guide; agents never drive the exploit. Build-side work starts on the flashed device, from provisioning onward, over ADB — the plan's no-exploit rule gains this one explicit, owner-approved exception. ADR 0007's provisional no-go is superseded for this device.

This packet's on-device checks (the ADR 0001 item 6 list, screen, sensors, sideload) move to P2.7, whose first step is a probe of the owner-flashed device; the LineageOS device, not stock firmware, is what gets measured. #33 (P2.7) is unblocked and waits on the owner's flash.

Sources (read in full, 2026-11-21): the XDA unlock thread "[UNLOCK][ROOT][TWRP][UNBRICK] Amazon Echo Show 8 2nd Gen / 2021 (athena)" (xdaforums.com/t/…athena.4804958), the XDA ROM thread "[ROM][UNOFFICIAL][11][athena] LineageOS 18.1 for the Amazon Echo Show 8 (2021)" (xdaforums.com/t/…athena.4805400), and FTVDB's athena firmware catalog (ftvdb.com/echo/firmware/com.amazon.athena.android.os/). ADR 0026's "Verified public sources" section records what each says and labels the two claims it could not verify in the sources' own words (stay off Wi-Fi until unlocked; Amazon OTAs stop). The spec-side comment on #32 was not used as a source.
